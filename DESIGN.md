# DESIGN.md — LNT v2 (Location Network Tester)

## 1. Архитектура информации и разделы (Information Architecture)

Интерфейс LNT v2 спроектирован как единый рабочий инструмент (workbench) исследователя электрических сетей. Он разделен на следующие функциональные области:

1. **Подготовка (Prepare)**: Выбор профилей оборудования, калибровки, параметров входа CH1/CH2, а также управление метаданными локации (outlet, circuit, damper).
2. **Захват (Capture)**: Запуск одиночных или серийных измерений, отображение активной задачи, прогресса серии и прерывание/отмена.
3. **Инспекция (Inspect)**: Детальный анализ выбранной сессии, просмотр спектра мощности (PSD), спектрограммы (STFT), осциллограммы и списка зарегистрированных событий/импульсов.
4. **Эксперименты (Experiments)**: Группировка сессий по протоколам (A/B, A/B/A, повторные серии), оценка эффектов, доверительных интервалов и дрейфа.
5. **Отчёты (Reports)**: Генерация научных отчетов с полной прослеживаемостью (provenance), метаданными и ограничениями.
6. **Настройки (Settings)**: Управление путями сессий, базами данных, резервным копированием и восстановлением.

## 2. Сетка и раскладка (Layout & Breakpoints)

### 2.1. Desktop (1280px и шире) — Трехпанельный режим (Tri-pane Layout)
Интерфейс использует фиксированную по высоте трехпанельную раскладку:
- **Левая панель (Каталог / Catalog)**: Ширина `320px`–`360px`. Содержит список сессий, поиск и фильтры. Владеет собственной вертикальной прокруткой.
- **Центральная панель (Рабочая область графиков / Plot Workspace)**: Занимает всю оставшуюся свободную ширину (`flex: 1`). Содержит вкладки графиков (спектр, спектрограмма, осциллограмма, события). Владеет собственной прокруткой.
- **Правая панель (Инспектор контекста / Context Inspector)**: Ширина `360px`–`400px`. Отображает метаданные, аудит-лог изменений, параметры калибровки и примечания. Владеет собственной прокруткой.

**Правила владения прокруткой (Scroll Ownership)**:
- Документ (`body`) имеет `overflow: hidden` на десктопе.
- Каждая из трех панелей имеет независимый `overflow-y: auto`. Шапка приложения (`app-header`) зафиксирована сверху.

### 2.2. Tablet (от 768px до 1279px)
- Двухпанельный режим: Каталог и Рабочая область графиков отображаются бок о бок.
- Инспектор контекста сворачивается в выдвижную панель (drawer) или переносится под рабочую область.
- Прокрутка остается независимой для каталога и рабочей области.

### 2.3. Mobile (375px) — Режим фокуса (Focus Mode)
- Однопанельный режим: Отображается только одна активная панель в каждый момент времени.
- Переключение между панелями (Каталог, Графики, Инспектор) осуществляется через фиксированный нижний переключатель (tab bar / switcher).
- Документ (`body`) имеет `overflow-y: auto` и владеет прокруткой всей страницы. Горизонтальный скролл полностью запрещен (`overflow-x: hidden`).

## 3. Типографика и шрифты (Typography)

Используются исключительно локально поставляемые шрифты семейства IBM Plex:
- **IBM Plex Sans**: Для всех интерфейсных текстов, подписей, меток и описаний.
- **IBM Plex Mono**: Для идентификаторов сессий, путей к файлам, сырых данных, табличных чисел и формул.

### 3.1. Шрифтовая сетка (Type Scale)

| Роль | Размер / line-height | Вес (Weight) | Семейство (Family) |
|---|---|---|---|
| **Заголовок страницы (page)** | 22px / 28px | 600 (SemiBold) | IBM Plex Sans |
| **Заголовок раздела (section)** | 17px / 24px | 600 (SemiBold) | IBM Plex Sans |
| **Основной текст (body)** | 15px / 22px | 400 (Regular) | IBM Plex Sans |

Все числовые данные в таблицах используют свойство `font-variant-numeric: tabular-nums lining-nums` для выравнивания разрядов по вертикали.

### 4.2. Семантика A/B экспериментов (A/B Semantics)
Для обеспечения доступности для людей с нарушениями цветового зрения (colorblind-safe), различие между сессиями A и B кодируется не только цветом:
- **Сессия А (Cyan)**: Сплошная линия (`solid`), маркер круга (`●`), текстовая метка «А».
- **Сессия Б (Amber)**: Штриховая линия (`dashed`: `6px 4px`), маркер квадрата (`■`), текстовая метка «Б».

### 4.3. Спецификация фокуса (Focus Ring Spec)
- Все интерактивные элементы при навигации с клавиатуры (`:focus-visible`) должны иметь четко видимую рамку фокуса.
- Ширина рамки фокуса: не менее `2px`.
- Смещение рамки фокуса (`outline-offset`): `2px`.
- Цвет рамки фокуса: `--lnt-accent-a` (или `Highlight` в режиме Forced Colors).
- Контраст рамки фокуса относительно фона должен быть не менее `3:1`.

### 4.4. Токены анимации и движения (Motion Tokens)
Анимация используется исключительно для сообщения состояния (hover, press, disclosure) и не должна быть декоративной.

```css
:root {
  --lnt-motion-fast: 100ms;
  --lnt-motion-standard: 160ms;
  --lnt-ease-standard: cubic-bezier(0.2, 0, 0, 1);
}
```

При включенном системном режиме уменьшения движения (`@media (prefers-reduced-motion: reduce)`) все переходы и анимации полностью отключаются (`transition: none !important; animation: none !important;`).

### 4.5. Палитра матрицы спектрограммы (Spectrogram Matrix Palette)
Матрица мощности (дБ) отображается перцептивно упорядоченной шкалой из девяти ступеней — от темносинего (шум/отсутствие сигнала) к золотому (максимум). Шкала привязана к семейству `--lnt-accent-a` и завершается тёплым highlight-акцентом; монотонный рост относительной яркости WCAG проверяется тестом, каждая ступень отличима от канвы обеих тем (§4.1).

| Ступень | Hex |
|---|---|
| min → max | `#1e3048` `#173a56` `#0f5f86` `#0f83a8` `#2aa7bd` `#4db9b4` `#7ccbb0` `#c9dc74` `#ffe066` |

Нецветовые альтернативы матрицы (обязательные): числовая шкала visualMap с подписями дБ, сводка видимого окна (`aria-live`), выгрузка матрицы тайла и сводки в CSV.

## 5. Матрица состояний компонентов (Component State Matrix)

Каждый компонент интерфейса должен корректно обрабатывать и отображать следующие состояния на русском языке:

### 5.1. Пустое состояние (Empty State)
- **Каталог**: «Сессии не найдены. Измените параметры фильтрации или запишите новую сессию.»
- **Графики**: «Данные для отображения отсутствуют. Выберите сессию из каталога слева.»
- **Сравнение A/B**: «Для сравнения необходимо выбрать две совместимые сессии.»

### 5.2. Состояние загрузки (Loading State)
- **Каталог**: «Загрузка списка сессий…»
- **Графики**: «Построение спектра мощности…» (с отображением реального прогресса, без бесконечных спиннеров).

### 5.3. Состояние ошибки (Error State)
- Отображается в виде встроенного баннера с `role="alert"`.
- Текст ошибки должен содержать понятное описание проблемы и конкретный следующий шаг для пользователя.
- Пример: «Ошибка подключения к устройству. Проверьте USB-кабель и убедитесь, что драйвер WinUSB установлен через Zadig. [Повторить проверку]»

### 5.4. Состояние прерывания (Interrupted State)
- Применяется к задачам анализа или захвата, которые были аварийно остановлены (например, при перезапуске сервера).
- Текст: «Задача была прервана из-за перезапуска сервера. Данные сохранены частично. [Запустить анализ заново]»

### 5.5. Состояние повреждения данных (Corrupt State)
- Применяется к сессиям, у которых поврежден манифест или отсутствуют ключевые файлы данных (`ch1.npy`).
- Текст: «Сессия повреждена. Не удалось прочитать файл манифеста или сигнальные данные. Путь: C:\Users\Кирилл\Очень\Длинный\Путь\...»

## 6. Доступность и интерактивность (Accessibility & Interaction)

- **Размер интерактивных элементов**: Все кнопки, ссылки, поля ввода и элементы списков имеют минимальный размер интерактивной области `44px` по высоте/ширине для надежного сенсорного и курсорного ввода.
- **Клавиатурная навигация**: Логичный порядок обхода по клавише `Tab` (Skip-link → Шапка → Каталог → Рабочая область → Инспектор).
- **Масштабирование**: При увеличении масштаба страницы до `200%` интерфейс перестраивается без появления горизонтальной прокрутки страницы и без перекрытия элементов управления. Длинные пути файлов и идентификаторы сессий корректно переносятся или сокращаются с помощью многоточия.

## 7. Глоссарий терминов (Russian Terminology Glossary)

Для обеспечения терминологической строгости в интерфейсе используются следующие русские эквиваленты:

- **Каталог (Catalog)**: Физическая папка на диске в корневом каталоге сессий (например, `capture-001`). Используется как уникальный идентификатор сессии.
- **Метка (Label)**: Произвольный текстовый тег, задаваемый пользователем в метаданных сессии (например, `стенд-А`, `самошум`). Используется для фильтрации и поиска.
- **Папка (Folder)**: Логическая группировка сессий в интерфейсе (не изменяет структуру файлов на диске).
- **Сессия (Session)**: Набор файлов одного измерения (манифест, сигналы, метрики, спектры).
- **Захват (Capture)**: Процесс аппаратного считывания сигнала с осциллографа.
- **Самошум (Self-noise)**: Базовая запись с терминированными входами для компенсации собственного шума прибора.

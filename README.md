Профили симуляции: `bad`, `bad-damped` (пик на 22.4 кГц ниже на ~12 дБ),
`quiet`, `sync-only`, `async-heavy`.

Коды выхода: `0` — успех; `2` — некорректный вход/данные (короткая запись,
битый манифест, слабый CH2); `3` — устройство недоступно (нет драйвера, нет
устройства, оборвался поток); `1` — провал selftest. Ошибки печатаются одной
строкой в stderr, без traceback.

## Интерфейс (lnt ui)

Установите зависимости веб-интерфейса:

```powershell
uv sync --python 3.12 --extra ui
```

Запустите панель:

```powershell
uv run lnt ui
uv run lnt ui --root D:\ses --port 8765 --no-browser
```

По умолчанию корень сессий: `~\lnt-sessions`, порт: `8765`. Команда печатает
`LNT UI: http://127.0.0.1:8765/` и открывает браузер после проверки готовности
API. Флаг `--no-browser` отключает открытие браузера. `Ctrl+C` останавливает
сервер. Без extra `ui` команда завершается с кодом `2` и сообщением
`интерфейс не установлен: pip install 'lnt[ui]' (см. README)`.

- **Устройство**: проверяет цепочку драйвер -> устройство -> прошивка и выводит
  подсказки по Zadig и VID `04B4`/`04B5`; см. [«Подготовка железа»](#подготовка-железа-windows-один-раз).
- **Симуляция**: создаёт синтетические сессии по профилю, с меткой, повторами и
  интервалом серии.
- **Захват**: задаёт длительность, частоту, диапазон CH1, метку, `self-noise`,
  число повторов и интервал.
- **Сессии**: показывает записи из выбранного корня, обновляет список и
  фильтрует его полем поиска по имени и метке без запросов к серверу;
  при пустом результате — состояние «По запросу ничего не найдено» с кнопкой
  «Очистить поиск».
- **Тема**: переключатель система/светлая/тёмная в шапке; выбор
  сохраняется в `localStorage` и переживает перезагрузку страницы.
- **Детальный анализ**: показывает манифест, метрики, log-log спектр и по кнопке
  загружает превью осциллограммы.
- **Сравнение A/B**: считает и показывает дельты по правилу `B - A`.
- **Selftest**: проверяет синтетический тракт без осциллографа.
- **Активная задача**: показывает стадию и позицию серии `i/N` через SSE;
  отмена серии выполняется после текущей сессии.

После каждой записанной сессии анализ запускается автоматически. Одновременно
выполняется только одна задача; попытка запустить вторую возвращает HTTP `409`.

Для графиков сервер применяет min/max-децимацию: спектр содержит не более
`5000` точек, превью осциллограммы не более `4000`. Исходные данные сессии не
меняются, ограничения относятся только к отображению.

Интерфейс работает офлайн: Plotly GL2D 3.7.0 и шрифты IBM Plex (пять WOFF2 +
OFL) вендорены, внешних запросов нет. Светлая и тёмная темы оформлены
дизайн-токенами (`DESIGN.md`, витрина `/static/showcase.html`).
Сервер слушает только `127.0.0.1`; Swagger/OpenAPI и ReDoc отключены. Все
изменяющие POST-запросы требуют заголовок `X-LNT-Request: ui`.

## Протокол измерений

- **≥ 100 циклов сети** на запись (дефолт 2.4 с при 50 Гц); меньше — exit 2.
- **Per-site baseline**: перед измерениями в локации снять `--self-noise`
  (фронтенды отключены, входы терминированы) — это самошум инструмента.
- **Сравнивать дельты, не абсолюты**: `lnt compare база текущая`. Калибровочная
  поправка АЦП не применяется (`calibration_used: false` в телеметрии) — на
  дельты внутри одной сессии измерений она не влияет.
- CH1 анализируется в полосе 3 кГц – min(3 МГц, 0.45·fs): band-спектр Уэлча,
  пики (частота — центроид полосы выше половинной мощности, Q = f0/FWHM);
  line-sync метрика иголок: σ_pk/μ_pk в окне доминирующей фазы и P_async/P_sync
  (среднее по циклам vs остаток). CH2 даёт синхронизацию (восходящие нули) и
  CV огибающей вершин 50 Гц.

### Режимы каналов

Захват и симуляция работают в двух режимах (`--channels 2|1`, в UI — селект «Каналы»):

| Режим | Железо | Синхронизация | Метрики |
|---|---|---|---|
| `2` (дефолт) | CH1 = ВЧ-фронтенд, CH2 = трансформатор 50 Гц | фазовая привязка к сети (восходящие нули CH2) | все |
| `1` | только CH1 (один пробник) | номинальные окна 20 мс без привязки к фазе | спектр, пики, μ_pk, σ/μ — да; P_async/P_sync, частота сети, CV CH2 — «н/д» |

В одноканальном режиме `ch2.npy` не записывается, в манифесте `ch2: null`,
а в `metrics.json` поле `sync_source: "nominal"` (вместо `"ch2"`) и недоступные
метрики равны `null`. Сравнение сессий разных режимов возможно: дельты
считаются только по общим метрикам, остальные помечаются «н/д».

### Режим качества сети (трансформатор 230:6)

Один пробник + трансформатор 230:6 = измеритель качества сети:

```
uv run lnt capture <каталог> --line-quality [--probe-multiplier 10] [--duration 10]
```

В UI — «Вход CH1» → «Трансформатор 230:6 — качество сети 50 Гц» (канал один,
самошум и базовая сессия не применяются). Пробник на вторичке трансформатора,
переключатель пробника в 10x (по умолчанию `--probe-multiplier 10`).

Анализ такой сессии (`session_type: "line_quality"`, `ch1_setup:
"transformer_line_probe_v1"`) пишет в `metrics.json` секцию `line_quality`
вместо needle-метрик: частота сети (интерполяция пика FFT), RMS фундаментала и
полный RMS вторички, THD по гармоникам H2–H40, таблица гармоник, crest-factor и
стабильность огибающей (CV поцикловых пиков). `spectrum.csv` не создаётся;
сравнение A/B для line-quality сессий не поддерживается (открывайте метрики
сессий по отдельности). Значения приведены к вторичке трансформатора: реальное
сетевое напряжение ≈ вторичка × (230 / U_xx), где U_xx — напряжение холостого
хода вашего трансформатора (для 2 ВА 230:6 обычно ~10 В, т.е. ×21–23).

## Формат сессии

```
<session>/
  manifest.json   # синтетика (simulate) и legacy: schema v1 — источник, тип, fs,
                  #   каналы, телеметрия, truth (для синтетики); без ch1_setup.
                  #   Реальный аппаратный захват: schema v2 с явным
                  #   дискриминированным ch1_setup (модель входа CH1)
  ch1.npy         # float32, вольты, ВЧ-пробник
  ch2.npy         # float32, вольты, трансформатор (отсутствует при --channels 1)
  metrics.json    # после analyze (schema v2): метрики иголок, пики спектра,
                  #   ch1_input_reference (status / reason_code / model_kind /
                  #   qualified_bin_count / total_bin_count / provenance)
  spectrum.csv    # после analyze: СЫРОЙ scope-plane PSD (frequency_hz, psd_v2_per_hz)
  spectrum_input_referred.csv  # приведённый ко входу избыточный PSD, если доступен;
                  #   иначе только заголовок (frequency_hz, input_referred_excess_psd_v2_per_hz)
```

Запись атомарна (каталог `.partial-*` + rename): сессия на диске либо целиком,
либо отсутствует.

**CH1 приведение ко входу (schema v2).** `metrics.json.ch1_input_reference`
машиночитаемо описывает, приведён ли спектр ко входу. При `status: "available"`
публикуются `model_kind` и provenance (`baseline_session_id`,
`qualification_rule_id`, `qualified_bin_count` / `total_bin_count`), а
`spectrum_input_referred.csv` содержит приведённый избыточный PSD. При
`status: "unavailable"` указывается `reason_code` (например
`manifest_schema_v1`), а приведённый CSV остаётся с одним заголовком.
Синтетические и legacy сессии (манифест schema v1) не несут `ch1_setup`,
поэтому их анализ (schema v2) всегда отдаёт `status: "unavailable"` с
`reason_code: "manifest_schema_v1"`. Отображаемый в UI `spectrum.csv` всегда
остаётся сырым scope-plane PSD и не выдаётся за приведённые ко входу данные.

```powershell
uv run --python 3.12 pytest -q          # полный набор, включая e2e сценарии CLI
node --test "tests/js/*.test.mjs"       # runtime-тесты фронтенда (node:test)
uv run --python 3.12 ruff check .       # правила: ALL (с точечными исключениями)
uv run --python 3.12 ruff format --check .
uv run --python 3.12 basedpyright       # typeCheckingMode = all
```

TDD-дисциплина: каждый модуль начинался с падающего теста; лимит 250 строк на
модуль контролируется тестами `test_module_size.py` (Python) и
`test_ui_js_module_size.py` (все first-party JS, включая тесты).

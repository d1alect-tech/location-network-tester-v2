# Пакетирование Windows-релиза

Публичный Windows-релиз версии 0.1.0 публикуется под `GPL-3.0-only`. На одной
странице GitHub Release размещаются четыре актива:

* `LNT-0.1.0-win64.zip`;
* `LNT-0.1.0-win64.zip.sha256`;
* `LNT-0.1.0-corresponding-source.zip`;
* `LNT-0.1.0-corresponding-source.zip.sha256`.

## Файлы поставки

| Файл или каталог | Содержание |
|---|---|
| `LNT.exe` | приложение |
| `SOURCE.txt` | имя и адрес Corresponding Source для этой версии |
| `LICENSE` | GPL версии 3 для LNT и объединённой сборки |
| `licenses/` | тексты лицензий компонентов |
| `THIRD_PARTY_NOTICES.md` | уведомления третьих сторон |
| `dependency-manifest.json` | точные версии, источники и хеши зависимостей |
| `distribution-policy.md` | техническая политика выпуска |
| `_internal/` | среда выполнения и код приложения |

Hantek6022API входит в сборку из коммита
`e65d52b0f2536e56eaadbb555e5d7b756409c36e` и указан как
`GPL-3.0-only`. Сборка рассчитана только на Hantek 6022BE.

Zadig и WinUSB не входят в архив. Оператор получает и устанавливает их
отдельно. Приложение не загружает эти компоненты.

Хеши бинарного архива и Corresponding Source публикуются в примечаниях к
релизу и в двух перечисленных файлах `.sha256`. SBOM и другие sidecar-файлы
можно добавить отдельно, но они не заменяют четыре обязательных актива.

Перед публикацией владелец запускает локальные гейты и
`git grep -n -I -F -- (Split-Path $env:USERPROFILE -Leaf)` для проверки
отслеживаемых файлов. CI только повторяет проверки и не публикует артефакты.

Принято свидетельство `sanitized-reference-host-verified`. Типизированное
состояние `device_absent` допустимо. Это не проверка на чистой виртуальной
машине и не подтверждение работы с физическим осциллографом.

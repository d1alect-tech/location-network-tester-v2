# Редизайн UI LNT: Scientific Workbench

Дата: 2026-07-26  
Статус: утверждённый дизайн, готов к планированию реализации

## Цель

Сделать локальную панель LNT визуально спокойнее и удобнее, не меняя API,
доменную модель или измерительный протокол. Интерфейс должен одинаково хорошо
работать днём и в полумраке, быстро подводить к захвату и отдавать основную
площадь анализу данных.

## Утверждённые решения

- Направление: Scientific Workbench.
- Темы: системная по умолчанию, ручные light/dark, локальное сохранение выбора.
- Шрифты: локальные IBM Plex Sans и IBM Plex Mono с кириллицей.
- Цвет: graphite neutrals, один muted petrol/cyan action accent, независимые
  semantic status ramps, cyan/ochre chart pair.
- Приоритет: measurement-first.
- Полный UX-scope: новая компоновка, progressive disclosure, поиск сессий,
  сворачиваемый манифест, lazy Plotly, favicon и metadata.

Точный token-контракт, контрасты и состояния находятся в корневом `DESIGN.md`.

## Архитектура экрана

### Header

Sticky-header содержит короткое имя LNT, якорную навигацию, корень сессий и
нативный theme selector. Минимальный theme-init выполняется до первого paint.

### Command area

Первая рабочая область объединяет:

1. компактный статус Hantek;
2. форму захвата с частыми полями;
3. активную задачу с реальным stage-progress.

Редкие параметры `Самошум`, `Повторы`, `Интервал` находятся в disclosure
`Серия и режим`. Payload остаётся прежним.

### Data workspace

На desktop каталог сессий занимает около 320px, анализ — остальную ширину. На
tablet каталог располагается над анализом; на mobile всё следует DOM-порядку.
Сравнение A/B идёт сразу после анализа. Симуляция и selftest находятся в
последнем разделе `Инструменты`.

## Компоненты

### Темы

Theme selector имеет значения `Системная`, `Светлая`, `Тёмная`. Выбор хранится
в `localStorage` (`lnt-theme`). В system-режиме `matchMedia` обновляет тему при
смене ОС; явный выбор имеет приоритет. На `<html>` хранится фактический
`data-theme="light|dark"`, поэтому CSS-компоненты не знают источник выбора.

### Захват

Каталог, длительность, диапазон и метка доступны без раскрытия. Primary-кнопка
на desktop находится в одной визуальной строке с основными настройками. Серия
и режим раскрываются нативным `details`; состояние полей сохраняется.

### Каталог сессий

Над списком появляется локальный поиск по имени и метке. Фильтрация не делает
API-запрос, не меняет сортировку и не уничтожает выбранную сессию, если она
временно скрыта. Состояние `ничего не найдено` содержит действие очистки.

### Анализ

Порядок: заголовок/статус → метрики → спектр → пики → waveform → сворачиваемый
манифест. Непроанализированная сессия сохраняет явное действие `Анализировать`.

### Графики

Глобальный Plotly-script удаляется из initial HTML. Loader вставляет локальный
vendor-script при первом запросе графика, возвращает общий Promise для
параллельных вызовов и отображает текстовый статус загрузки. Ошибка загрузки
показывает восстановительное действие, а не пустые оси.

### Сравнение

На desktop A, B и primary-action расположены компактной строкой; mobile
переходит в stack. Результат всегда показывает знак, направление и словесную
оценку там, где доменная семантика направления определена.

## Data flow и состояния

Backend и маршруты не меняются. Существующие вызовы `listSessions`,
`getSessionDetail`, `getSpectrum`, `getWaveform`, job SSE и compare остаются
источником истины.

Новый локальный state:

- `themePreference: system | light | dark`;
- `sessionQuery: string`;
- `plotlyLoadPromise: Promise | null`.

Theme state изолирован в небольшом модуле. Session query применяется только
при рендере каталога. Plotly loader не меняет payload графиков.

## Ошибки и восстановление

- API/domain errors продолжают проходить через общий inline error-banner.
- Ошибка поля остаётся рядом с полем и получает `aria-invalid`.
- Ошибка Plotly не делает сессию повреждённой; пользователь может повторить
  загрузку графика.
- Пустой результат поиска не является ошибкой.
- Theme initialization при недоступном localStorage безопасно возвращается к
  system без сообщения пользователю.

## Производительность

- Plotly 1.6MB исключается из initial load и загружается один раз по требованию.
- Локальный IBM Plex Sans 400 preload; другие WOFF2 загружаются по CSS demand.
- Никаких CDN, внешних изображений, telemetry или новой runtime-библиотеки.
- Фильтрация 200 сессий выполняется синхронно; virtualize не добавляется без
  измеренной необходимости.

## Доступность

- WCAG 2.2 AA в обеих темах; критические пары уже рассчитаны в `DESIGN.md`.
- DOM-порядок совпадает с mobile-порядком и клавиатурным маршрутом.
- Theme selector, details, form controls и buttons остаются нативными.
- Touch target минимум 44px; поля mobile минимум 16px.
- Статус не зависит только от цвета; A/B различаются подписью и solid/dash.
- Reduced motion отключает переходы; zoom 200% не создаёт горизонтальный scroll.
- Графики имеют таблицы и текстовые подписи.

## Адаптивность

- 375px: одна колонка, горизонтальная nav, reflow таблиц A/B.
- 768px: command area 2x2, захват на всю ширину, каталог над анализом.
- 1280px: command area во всю ширину, workspace 320px + flexible analysis.
- Документ владеет основной прокруткой; nested scroll разрешён только каталогу
  на tablet/desktop.

## Реализационные границы

В scope:

- `DESIGN.md`, HTML/CSS/JS темы и компоновки;
- локальные IBM Plex WOFF2 и `@font-face`;
- theme module, session filter, Plotly loader;
- SVG favicon и meta description;
- обновление тестов и полная browser QA.

Вне scope:

- backend/API/schema/CLI;
- новый режим live-stream;
- удаление или переименование существующих операций;
- UI framework, React, Tailwind или component library;
- внешние ресурсы;
- полнотекстовый backend-поиск и virtualized list;
- новые аналитические метрики.

## Критерии приёмки

- При открытии сразу видны готовность прибора и путь к захвату.
- Частый захват запускается без поиска нужной секции и без раскрытия редких
  параметров.
- Спектр получает основную ширину desktop.
- Light/dark не имеют вспышки неверной темы и сохраняют выбор.
- Первый экран не загружает Plotly до запроса графика.
- Все прежние операции и API-контракты проходят без изменений.
- Обе темы проходят WCAG AA и visual QA на трёх breakpoints.

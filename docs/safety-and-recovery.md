# Безопасность и восстановление LNT v2

Документ описывает диагностику перед захватом, состояния устройства, таксономию
ошибок, резервное копирование и восстановление после сбоев.

## Preflight-диагностика захвата

Перед стартом любого аппаратного захвата выполняется preflight: чистая проверка
параметров и окружения без побочных эффектов. Каждое замечание несёт стабильный
код, русское сообщение и ручное действие восстановления. Preflight никогда не
меняет настройки сам: он либо блокирует старт (severity `block`), либо
предупреждает (`warn`).

### Состояния устройства

Цепочка готовности backend → USB → прошивка сводится к одному из состояний.
Каждое состояние имеет детерминированное описание и действие оператора:

| Состояние | Что происходит | Действие |
|---|---|---|
| `backend_unavailable` | Backend Hantek/libusb недоступен | Установите extra `lnt[hantek]`, положите совместимую libusb-1.0.dll рядом |
| `driver_missing` | Устройство видно, WinUSB для его VID не установлен | Установите WinUSB через Zadig для обнаруженного VID |
| `device_absent` | Hantek DSO-6022BE не найден на USB | Проверьте кабель и порт; переустановка backend не нужна |
| `bootloader_vid` | Загрузочный VID 04B4, RAM-прошивка ещё не активна | Проверьте WinUSB для 04B4; прошивка грузится только явным захватом |
| `running_vid` | Рабочий VID 04B5, готовность handle не подтверждена | Закройте другие программы с осциллографом, повторите проверку |
| `handle_busy` | USB-handle занят другим процессом | Освободите устройство и повторите проверку |
| `firmware_missing` | Устройство открыто, RAM-прошивки нет | Запустите захват явно; диагностика прошивку не грузит |
| `firmware_upload_failed` | Прошлая загрузка прошивки упала | Переподключите устройство, проверьте firmware-файлы, повторите |
| `ready` | Всё готово | Действий не требуется |

Любое состояние кроме `ready` даёт preflight-blocker с кодом
`device_<состояние>`.

### Коды findings

| Код | Severity | Причина | Восстановление |
|---|---|---|---|
| `mode_setup_mismatch` | block | тип сессии не соответствует модели входа CH1 | RC для measurement, termination для self-noise, transformer для line-quality |
| `line_quality_requires_single_channel` | block | line-quality использует один канал CH1 | переключитесь в одноканальный режим вручную |
| `sample_count_overflow` | block | rate × duration вне допустимых пределов | уменьшите rate или duration |
| `insufficient_disk_space` | block | свободного места меньше требуемого (с запасом 1.2×) | освободите место или смените корень сессий |
| `session_root_not_writable` | block | корень сессий недоступен для записи | исправьте права или выберите другой каталог |
| `baseline_incompatible` | block | baseline не совпадает по source/rate/range/probe/setup или содержит клиппинг | снимите совместимый baseline |
| `line_quality_clipping_likely` | warn | пик вторички около 16 В при пробнике 10x может перегрузить диапазон | выберите диапазон 5 В вручную |
| `weak_signal_resolution` | warn | слабый RC-сигнал на диапазоне 5 В использует несколько LSB | при безопасном пике возьмите 0.5 В после пробной оценки |

## Состояния ошибок CLI

Таксономия привязана к кодам выхода; любая ошибка печатается одной строкой в
stderr, без traceback.

| Код выхода | Класс | Типовые причины |
|---|---|---|
| `0` | успех | |
| `1` | провал selftest | расхождение синтетического тракта с эталоном |
| `2` | некорректный вход/данные (`InputError`) | короткая запись, битый манифест, слабый CH2, неверные аргументы |
| `3` | устройство недоступно (`DeviceNotFoundError`) | нет драйвера, нет устройства, оборвался поток |

Иная ошибка считается дефектом программы и требует support-bundle (см. ниже).
Полная таксономия классов: [adr/ADR-0008](adr/ADR-0008-error-taxonomy.md).

## Диагностика поддержки

```powershell
lnt support-bundle LNT-support.zip
```

Состав фиксирован allowlist'ом, каждый член сопровождается SHA-256 в
`manifest.json`. Включаются версия схемы конфигурации (без значений: пути и
токены не выгружаются вовсе), диагностика устройства, версии зависимостей и
хвост структурного журнала. Сырые захваты не включаются никогда; приватные
заметки добавляются только явным флагом `--include-private-notes`.

## Backup и restore

Архив это ZIP с boundary-manifest v1: строгая схема, SHA-256 каждого члена,
проверка коллизий имён (включая case-fold) и провенанс (build ID, время,
исходные идентификаторы сессий и экспериментов).

```powershell
# создать архив явной выборки
lnt archive create backup.zip --root D:\ses --session D:\ses\after-upgrade --experiment EXP-001

# показать manifest архива
lnt archive list backup.zip

# проверить schema, limits и SHA-256
lnt archive verify backup.zip

# восстановить в один новый каталог (без записи: --dry-run)
lnt archive restore backup.zip --dest D:\restored --dry-run
lnt archive restore backup.zip --dest D:\restored
```

Правила безопасности архива:

* restore пишет только в **один новый пустой каталог** и отказывается
  перезаписывать существующее содержимое;
* враждебный архив (обход путей, дубликаты, чужая схема manifest) отклоняется
  до первой записи;
* `verify` можно запускать на любом носителе: проверяются все хеши и лимиты.

Рекомендуемый цикл: после каждой серии измерений создавать архив выборки,
хранить его на отдельном диске и периодически прогонять `archive verify`.

## Восстановление после сбоя

### Целостность каталога сессий

Каталог проекций восстанавливаем, сырые сессии никогда не переписываются:

```powershell
# состояние и health-счётчики
lnt catalog status --root D:\ses

# проверить drift без записи (--deep дополнительно хеширует содержимое raw-файлов)
lnt catalog verify --root D:\ses --deep

# полностью перестроить проекции из сырых данных
lnt catalog reindex --root D:\ses
```

Классы health сессии: `ok`, `corrupt_manifest`, `missing_files`, `partial`,
`duplicate_id`, `context_invalid`, `analysis_invalid`. Частичная сессия
(`.partial-*`, оставшаяся от прерванной записи) в анализ не попадает и видна
в фильтре health как `partial`.

### Аварийный порядок

1. Остановите приложение (закройте окно LNT.exe).
2. Скопируйте корень сессий целиком на другой диск: сырые данные важнее всего.
3. Соберите `lnt support-bundle` и приложите журнал `%LOCALAPPDATA%\LNT\logs`.
4. На новой копии корня выполните `catalog verify --deep`, затем
   `catalog reindex`.
5. БД каталога (`%LOCALAPPDATA%\LNT\catalog.sqlite3`) можно удалить целиком:
   она полностью производная и перестраивается reindex'ом.

### Неизменяемые эталоны проекта

Разработка ведётся против замороженных эталонов: исходное дерево оригинального
проекта и реальный корень сессий защищены hash-receipts. Скрипт
`scripts/Assert-Pristine.ps1` перехеширует оба дерева и падает при любом
расхождении; receipts никогда не обновляются автоматически. Подробности:
[pristine-enforcement.md](pristine-enforcement.md).

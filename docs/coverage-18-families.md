# Покрытие 18 семейств дескрипторов (characterization program)

Статус: Wave 4 todo 11 — F01 и F02 реализованы end-to-end, остальные 16 — `not_computed`.
Реализовано семейств: 2/18 (F01 `synchronous_relative_harmonic_dft` и F02
`template_gain_delay_least_squares` через один `run_characterization` seam + бандл 18 + API/UI).
Готовы 8 shared-корней (`src/lnt/characterization/shared.py:64`).
E2E-шаблон: `tests/analysis_v2/test_f01_e2e_template.py` (эталон `simulate_session(profile=bad, 500 кГц, 2.4 с, seed 6022)`, `dirname == session_id`; прогон → чтение бандла → cache-hit → recipe-change ⇒ новый ключ → raw-хеши неизменны; переиспользовать для Phase 2+). На эталоне CH1 F01 PARTIAL (`grid_unstable`, `phase_unstable`) — ожидаемо: CH1 — иголки без несущей 50 Гц; AVAILABLE требует analytic-синтетика (`tests/characterization/test_f01_phase_cycle.py`). fs-матрица: 500 кГц — эталон, 8 МГц — declared codes halo-семейств (`.omo/evidence/task-3-characterization-18-families.md:68-89`).
F02 на эталоне PARTIAL с подобранными значениями (`baseline_unavailable`, `below_snr`; 319 из 927
событий подобраны) — иголки CH1 детектор размечает как корневые события, поэтому это не codes-only
путь (`tests/analysis_v2/test_f02_e2e_reduced.py`). AVAILABLE-путь проверяется импульсной
periodic-волной 50 Гц, где шаблон цикла совпадает с разметкой детектора (медиана `a` = 1,0;
среднее 0,866 утянуто краевыми событиями с урезанным спаном). Шаблон F01 — один цикл на сетке
`theta` из 1000 точек, независимой от `fs`, поэтому перед корреляцией он ресэмплируется на сетку
записи (`fs/f1` сэмплов, линейная интерполяция — залоченное правило F01):
`f02_amplitude_shape.resample_cycle_template`.
Пробел спеки: при пустом инвентаре событий объявленный словарь из пяти кодов
(`method-notes-families-1-9.md:145-146`) не содержит кода «событий не размечено вовсе». Выбран
`baseline_unavailable` — без события нет пары интервалов длины события для медианы; `below_snr`
заявлял бы измерение, которого не было. Решение закреплено тестом
`test_empty_event_inventory_is_unavailable_without_fabricated_values`.
Пробел спеки (второй): пяти объявленным кодам не соответствует код «остаток выше
`rho_max=0.25`». Отклонение по rho маппируется на `below_snr` — отношение сигнала к
остатку собственной подгонки ниже порога, фабрикации нет, но потребитель не отличит
«тихое событие» от «шаблон не объясняет событие». Требует решения владельца до F08,
где тот же пробел повторится.
Ограничение оценки (замерено на импульсной волне 50 Гц): спан короче одного цикла
шаблона подгоняется против усечённого и дополненного нулями шаблона и смещает `a`
вниз — среднее 0,866 против медианы 0,9994. Смещение не мониторится; зафиксировано
как ограничение и в этом срезе не исправлено.
Усечённый хвост событий за `maximum_events` виден в поддержке: `sample_count` — весь
инвентарь, `missing_count` включает и усечённые, и отвергнутые; число усечённых
отдельно публикуется сводкой `f02_omitted_event_count`.
У состояния PARTIAL маска валидности — все единицы и информации не несёт: отвергнутые
слоты исключены из массивов (`missing_rule=exclude_and_count`), а не замаскированы;
маска нужна только для инварианта `models.py:101-104`.
Метод F01 `synchronous_relative_harmonic_dft` зафиксирован (`src/lnt/analysis_store/characterization_contract.py:13-17`):
окно 0,2 с, минимум 12 окон, Hmax 40, Rmin 0,8, H1 ratio ≥ 0,95.

Идентификаторы методов ниже — дословно из `src/lnt/analysis_store/characterization_contract.py:13-117`.
Русские строки продукта сохранены там, где их используют существующие документы
(плоскость осциллографа / трансформатора, `V2s` — не джоули и не энергия, коды ошибок CLI).

## Порядок Phase 2+ (цепочки зависимостей)

Корень Phase 2 — F06: ни от какого семейства не зависит (только shared-корни:
полоса, детренд, Hilbert-контекст `A=16384` — `shared-computations.md:88-91`).

1. `F02 ← F01`: F02 берёт шаблон `f01_phase_cycle:x_template_v` как `v(t)`
   (`method-notes-families-1-9.md:128`, контракт `template_family_id template_field` —
   `characterization_contract.py:18-22`). Без готового F01 F02 недоступен
   (`template_unavailable`).
2. `F04 ← F06`: путь несущей (a) строится из развёрнутой фазы F06
   (`method-notes-families-1-9.md:213-216`; контракт `carrier_source_family_id` —
   `characterization_contract.py:29-33`). Без F06 — только путь сети (b) либо
   `carrier_unavailable`.
3. `F11 ← F15 ← F10`: F11 исполняется после F15 на его стандартизации и четырёх
   канонических медоидах (`method-notes-families-10-18.md:84-86`; контракт
   `mode_source_family_id` — `characterization_contract.py:66-71`); F15 требует
   результат F10 как один из семи признаков (`method-notes-families-10-18.md:269-272`,
   `285-288`). Порядок: F10 → F15 → F11; без F15 F11 недоступен (`mode_unavailable`).
4. `F06 root-only`: F06 — корень, остальные семейства от него зависят только через
   цепочку 2 (F04). F06 сам ни за кем не стоит.

Остальные семейства (F03, F05, F07–F09, F12–F14, F16–F18) зависят только от
shared-корней (фаза CH2 по фронтам, 64-бинные средние, STFT/полосы/события/чанки —
`method-notes-shared-computations.md:22-33`, `78-91`) и между собой не упорядочены.

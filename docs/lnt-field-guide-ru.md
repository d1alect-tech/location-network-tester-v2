## 1. Установить Git и uv

Откройте PowerShell.

Установите [Git for Windows](https://git-scm.com/download/win), затем откройте
новое окно PowerShell и проверьте установку:

```powershell
git --version
```

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Снова откройте PowerShell и проверьте:

```powershell
uv --version
```

Отдельно устанавливать Python обычно не требуется: `uv` загрузит Python 3.12.

## 2. Скачать и установить LNT

```powershell
cd $env:USERPROFILE\Documents
git clone --branch master https://github.com/d1alect-tech/location-network-tester-v2.git
cd location-network-tester-v2
uv sync --python 3.12 --extra ui --extra hantek
uv run lnt --help
```

Node.js для обычного запуска не нужен: собранный интерфейс уже находится в
репозитории.

Узнайте расположение Python окружения:

```powershell
uv run python -c "import sys; print(sys.executable)"
```

Положите совместимую 64-битную `libusb-1.0.dll` из источника, указанного в
документации [Hantek6022API](https://github.com/Ho-Ro/Hantek6022API), рядом с
показанным `python.exe`. Обычно это выглядит так:

```text
.venv\Scripts\python.exe
.venv\Scripts\libusb-1.0.dll
```

## 3. Проверить LNT без осциллографа

```powershell
$demo = "$env:USERPROFILE\lnt-demo"
uv run lnt simulate --profile quiet --out "$demo\syn-quiet-seed6022" --seed 6022 --label "smoke-test"
uv run lnt analyze "$demo\syn-quiet-seed6022"
uv run lnt ui --root $demo
```

Браузер должен открыться на `http://127.0.0.1:8765/`. Проверьте, что сессия
видна в **«Каталоге»**, а в **«Инспекции»** открываются метрики и спектр.
Затем остановите UI сочетанием `Ctrl+C` в PowerShell.

## 4. Подготовить USB-драйвер

1. Убедитесь, что extra Hantek установлен, а `libusb-1.0.dll` лежит рядом с
   Python окружения.
2. Подключите Hantek по USB и запустите [Zadig](https://zadig.akeo.ie/) от
   имени администратора.
3. Включите `Options` → `List All Devices`, найдите Hantek с VID `04B4`,
   внимательно проверьте выбранное устройство и установите для него WinUSB.
4. Выполните из каталога репозитория:

   ```powershell
   uv run lnt selftest
   ```

`selftest` проверяет вычислительный тракт без железа. Готовность самого Hantek
проверяется в интерфейсе на шаге 6.

При первом настоящем захвате LNT загружает прошивку в RAM осциллографа, после
чего VID меняется с `04B4` на `04B5`. Если устройство после первой попытки
«пропало», снова откройте Zadig и установите WinUSB для `04B5`, затем повторите
захват. Прошивка в RAM загружается только захватом, а не диагностикой.

## 5. Создать отдельный корень сессий и запустить LNT

Не пишите прямо на флешку: сначала завершите атомарную запись на локальный
диск, затем создайте и проверьте архив.

```powershell
$root = "$env:USERPROFILE\lnt-sessions-friend"
New-Item -ItemType Directory -Force $root | Out-Null
uv run lnt ui --root $root
```

Браузер откроется на `http://127.0.0.1:8765/`. Вкладки интерфейса:
**«Каталог»**, **«Захват»**, **«Инспекция»**, **«Эксперименты»**,
**«Отчёты»**, **«Настройки»**. Работает только один экземпляр LNT; занятый
порт или второй экземпляр дают ошибку вместо параллельного запуска.

## 6. Проверить Hantek

1. Откройте **«Захват»**.
2. В **«Источник записи»** выберите **«Осциллограф Hantek 6022BE»**.
3. Нажмите **«Проверить устройство»**.

Типичные действия по результату диагностики:

- `backend_unavailable` — установить extra `hantek` и проверить DLL;
- `driver_missing` — установить WinUSB для обнаруженного VID;
- `device_absent` — проверить USB-кабель и порт;
- `handle_busy` — закрыть фирменную программу Hantek/OpenHantek;
- `firmware_missing` — прошивка должна загрузиться при явном захвате;
- `ready` — дополнительных действий не требуется.

В текущей реализации проверка устройства не загружает RAM-прошивку. Поэтому
до первого захвата состояние может быть не `ready`; ориентируйтесь на
показанное LNT действие и сценарий `04B4` → `04B5` выше.

## 7. Снять baseline самошума локации

Baseline действительно вычитается при последующем анализе, но только если
измерение явно ссылается на него. Вычитание выполняется для PSD CH1 и только в
квалифицированных частотных бинах; сырой `spectrum.csv` не изменяется.

### Подключение

1. Полностью отключите RC-фронтенд и трансформатор от Hantek.
2. Установите на CH1 и CH2 BNC-терминаторы 50 Ом.
3. К Hantek должен быть подключён только USB.

### Запись

Закройте UI сочетанием `Ctrl+C`, если он ещё запущен, и выполните:

```powershell
uv run lnt capture `
  --out "$root\friend-noise" `
  --self-noise `
  --termination-ohm 50 `
  --duration 2.4 `
  --rate 8000000 `
  --range 5 `
  --label "friend-noise"
```

После успешной записи каталог `$root\friend-noise` должен содержать как
минимум `manifest.json`, `ch1.npy` и `ch2.npy`.

> Baseline и основное RC-измерение должны совпадать по источнику, частоте
> дискретизации, диапазону CH1, множителю пробника и использованию калибровки;
> ни одна запись не должна клиппировать. Поэтому не меняйте `--rate` и
> `--range` между командами ниже. Длительность тоже оставьте одинаковой, чтобы
> совпала частотная сетка Welch.

## 8. Снять основное RC-измерение с автоматическим вычитанием baseline

Этот шаг выполняйте только с готовым безопасным RC-фронтендом:

- CH1 — RC-фронтенд;
- CH2 — вторичная сторона изолирующего трансформатора для фазовой привязки;
- землю щупа нельзя соединять с первичной сетью 230 В.

Выполните серию из пяти повторов:

```powershell
uv run lnt capture `
  --out "$root\friend-rc" `
  --baseline "../friend-noise" `
  --duration 2.4 `
  --rate 8000000 `
  --range 5 `
  --repeat 5 `
  --interval 30 `
  --label "friend-rc"
```

Получатся каталоги `$root\friend-rc-001` … `$root\friend-rc-005`. В каждом
`manifest.json` ссылка `baseline_session` будет указывать на
`../friend-noise`. После захвата выполните анализ каждой сессии:

```powershell
1..5 | ForEach-Object {
  $session = "$root\friend-rc-{0:D3}" -f $_
  uv run lnt analyze $session
}
```

Если RC-компоненты были измерены оператором, добавьте к `capture` их реальные
значения одновременно:

```text
--rc-r-ohm <R> --rc-c1-nf <C1> --rc-c2-nf <C2>
```

Без этих флагов LNT фиксирует номинальную модель `100 Ом / 10 нФ / 10 нФ`.

> В текущем UI поле **«Базовая сессия (самошум)»** существует, но аппаратный
> preflight блокирует заполненный baseline до разрешения ссылки. Поэтому для
> гарантированного автоматического вычитания используйте показанный выше CLI
> с `--baseline`, а UI — для инспекции результатов.

## 9. Отдельно измерить качество сети

Этот режим не принимает self-noise baseline и не сравнивается командой
`lnt compare`: он рассчитывает отдельные показатели частоты, RMS, THD,
гармоник и crest-factor по вторичной стороне трансформатора.

### Подключение

1. Отключите RC-фронтенд.
2. Подключите CH1 только ко вторичной обмотке исправного изолирующего
   трансформатора 230:6.
3. И наконечник, и земля щупа должны оставаться на вторичной стороне.
4. Переведите щуп в положение `10x`.

### Запись

```powershell
uv run lnt capture `
  --out "$root\friend-line" `
  --line-quality `
  --probe-multiplier 10 `
  --range 5 `
  --duration 2.4 `
  --rate 8000000 `
  --repeat 5 `
  --interval 30 `
  --label "friend-line"
```

Проанализируйте серию:

```powershell
1..5 | ForEach-Object {
  $session = "$root\friend-line-{0:D3}" -f $_
  uv run lnt analyze $session
}
```

## 10. Проверить результаты в интерфейсе

Снова запустите:

```powershell
uv run lnt ui --root $root
```

Для каждой сессии:

1. Откройте её в **«Каталоге»** и перейдите в **«Инспекцию»**.
2. Проверьте источник, длительность, частоту дискретизации и наличие нужных
   каналов.
3. Убедитесь, что нет предупреждений о клиппинге.
4. Для `friend-rc-*` найдите статус приведения CH1 ко входу: baseline должен
   быть доступен, а не помечен `unavailable`. Сырой спектр и спектр после
   baseline-коррекции — разные представления; вычитание не перезаписывает
   исходные данные.
5. Просмотрите метрики, спектр, спектрограмму и события.

Для спектрального просмотра оставьте окно **Hann** и RBW **50 Гц**. Сессии A и
B сравнивайте только при одинаковых окне, RBW, аппаратуре и настройках.

## 11. Перенести записи на флешку

Остановите UI через `Ctrl+C`. Создайте один проверяемый архив всего корня:

```powershell
$archive = "$env:USERPROFILE\Desktop\lnt-friend.zip"
uv run lnt archive backup $archive --root $root
uv run lnt archive verify $archive
```

Скопируйте `lnt-friend.zip` на флешку и проверьте уже флешечную копию:

```powershell
uv run lnt archive verify "E:\lnt-friend.zip"
```

Замените `E:` фактической буквой флешки. Убедитесь, что обе проверки успешны,
и только после этого извлекайте носитель.

Дома восстановите архив в новый пустой каталог:

```powershell
uv run lnt archive restore "E:\lnt-friend.zip" --dest "$env:USERPROFILE\lnt-friend-restored"
```

Не переносите только `metrics.json` или `spectrum.csv`: для повторного анализа
нужны полные каталоги сессий, включая baseline и сырые `ch*.npy`.

## 12. Завершить работу

1. Дождитесь конца текущего захвата или серии.
2. Убедитесь, что архив создан, проверен и скопирован на флешку.
3. Остановите LNT сочетанием `Ctrl+C`.
4. Обесточьте измерительную схему.
5. Только затем отсоедините щупы, трансформатор и USB.

## Как интерпретировать результаты

- Self-noise baseline устраняет измеренный вклад тракта из CH1 PSD; это не
  делает разные ПК или измерительные схемы автоматически идентичными.
- Для сравнения условий используйте одинаковый Hantek, фронтенд, кабели,
  частоту, диапазон, длительность и методику; меняйте только исследуемое
  условие.
- LNT не является сертифицированным средством измерений, а некалиброванное
  напряжение нельзя выдавать за калиброванное.
- Связь электрических помех с воспринимаемым input lag остаётся гипотезой;
  совпадение изменений не доказывает причинность.

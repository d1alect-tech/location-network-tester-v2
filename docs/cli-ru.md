# Справочник CLI: `lnt`

LNT это одна консольная команда `lnt` с субкомандами: симуляция, захват с
осциллографа, анализ, сравнение, каталог сессий, архивы, эксперименты и
диагностика. Справочник описывает всю поверхность командной строки: назначение,
флаги, примеры и коды выхода. Он дополняет [README](../README.md) и рассчитан
на работу из корня открытого репозитория.

## Как читать этот справочник

Команды выполняются из корня репозитория, префикс один у всех:

```powershell
uv run --python 3.12 lnt <субкоманда> [флаги]
```

В переносимой сборке те же субкоманды принимает `LNT.exe`: вызов с субкомандой
работает как CLI, вызов без аргументов открывает графический интерфейс с
собственными флагами `--root`, `--port`, `--no-browser`.

- У каждой команды и субкоманды есть `-h`/`--help`, текст справки русский.
- Ошибка печатается одной строкой в stderr, трейсбеков нет: `Ошибка: …` для
  входных данных и данных, `Устройство: …` для железа.
- При перенаправлении вывода в файл или пайп включите UTF-8, иначе
  Windows-консоль отдаёт кириллицу устаревшей кодовой страницей и текст
  приходит битым:

```powershell
$env:PYTHONUTF8 = "1"
```

- Таблицы флагов имеют колонки «флаг, аргумент, по умолчанию, что делает».
  Позиционные аргументы помечены словом «позиционный».
- Примеры выполняются во временном каталоге вне репозитория и не требуют
  осциллографа, кроме раздела `lnt capture`:

```powershell
$demo = "$env:TEMP\lnt-cli-demo"
New-Item -ItemType Directory -Force $demo | Out-Null
$demo2 = "$env:TEMP\lnt-cli-exp"
New-Item -ItemType Directory -Force $demo2 | Out-Null
```

Первый корень держит сессии для рабочего цикла, второй нужен примерам
`lnt experiment` и `lnt hypothesis`: их хранилища пишутся рядом с корнем
сессий, и так они не попадают в `$demo`.

- Вывод команд в примерах снят с реальных запусков LNT 0.1.2 на 64-битной
  Windows. Пути, счётчики и метки времени будут вашими.

LNT не выносит вердиктов. Недоступная величина печатается как недоступная, с
причиной; число на её место не подставляется. Напряжение не калибровано, LNT
не является поверенным средством измерений, совпадение изменений не
доказывает причинность.

## Коды выхода

| Код | Константа | Когда возвращается |
|---|---|---|
| 0 | `EXIT_OK` | Успех. Остановка `lnt ui` по `Ctrl+C` тоже возвращает 0. |
| 1 | `EXIT_SELFTEST_FAIL` | `lnt selftest` не прошёл. Внутренняя ошибка движка `lnt ripple`. Найденное расхождение каталога в `lnt catalog verify`. |
| 2 | `EXIT_INPUT` | Неверный вход или данные: `InputError`, `AnalysisError`, `ArchiveError`, отсутствующие файлы и ключи. Ошибки использования argparse тоже дают 2. Для `lnt ui` дополнительно: порт вне диапазона, занятый порт, второй экземпляр, отсутствие зависимостей extra `ui`. |
| 3 | `EXIT_DEVICE` | `DeviceNotFoundError`: осциллограф недоступен или занят. Только путь захвата. |

Код последней команды в PowerShell даёт `$LASTEXITCODE`.

## Перечень субкоманд

Вывод `uv run --python 3.12 lnt --help`:

```text

           {archive,sessions,context,profiles,reindex,experiment,hypothesis,simulate,capture,analyze,ripple,compare,ui,support-bundle,selftest,catalog}
           ...

Location Network Tester: захват и анализ сетевых помех (Hantek 6022BE)

positional arguments:
  {archive,sessions,context,profiles,reindex,experiment,hypothesis,simulate,capture,analyze,ripple,compare,ui,support-bundle,selftest,catalog}
    archive             проверенные экспорт, backup и restore
    experiment          эксперименты и расчёты
    hypothesis          аудитируемые гипотезы
    simulate            синтетическая сессия по профилю
    capture             захват с Hantek 6022BE
    analyze             анализ сессии: metrics.json + spectrum.csv
    ripple              риппл/шум сессии: сайдкар ripple.json (аддитивно, без
                        вердиктов)
    compare             таблица дельт двух сессий (B - A)
    ui                  локальный веб-дашборд (localhost)
    support-bundle      ZIP-диагностика для поддержки (без секретов и
                        захватов)
    selftest            синтетическая самопроверка пайплайна
    catalog             обслуживание каталога сессий

options:
  -h, --help            show this help message and exit
```

Вывод снят при перенаправлении и свёрстан в 80 колонок; широкий терминал
переверстает тот же текст.

Секции ниже идут в порядке рабочего цикла: симуляция и захват, анализ, риппл,
сравнение, интерфейс. Затем данные: архивы, каталог, запросы, контекст,
профили, статус переиндексации. Затем эксперименты и гипотезы, в конце
сервисные команды. Файлы для примеров экспериментов и гипотез собраны в
[приложении](#приложение-файлы-примеров).

## `lnt simulate`

Назначение: синтетическая сессия по профилю сигнала. Осциллограф не нужен,
истина профиля известна заранее, аналитический корпус истин живёт в
`tests/science/corpus.py`. Синтетика это штатный способ посмотреть весь тракт
без железа.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--profile` | `async-heavy`, `bad`, `bad-damped`, `quiet`, `sync-only` | обязателен | профиль сигнала |
| `--out` | путь | обязателен | каталог новой сессии |
| `--duration` | число, с | 2.4 | длительность записи; минимум 100 периодов сети, короче отклоняется с кодом 2 |
| `--rate` | число, Гц | 500000.0 | частота выборки |
| `--seed` | целое, `>= 0` | 6022 | семя генератора |
| `--channels` | `1` или `2` | 2 | `1`: только CH1, один пробник, без фазовой привязки; `2`: CH1+CH2 |
| `--label` | текст | не задан | метка сессии, попадает в `parameters['label']` манифеста |
| `--repeat` | целое | 1 | число сессий серии, каталоги `<out>-001..-NNN` |
| `--interval` | число, с | 0.0 | период между стартами сессий серии, сетка `t0 + i*interval` |

Коды выхода: 0 (успех); 2 (неверный вход: нечисловые или бесконечные
значения, отрицательное семя, неизвестный профиль, незаписываемый путь).
Устройства в этой команде нет, код 3 не встречается.

Примеры:

```powershell
uv run --python 3.12 lnt simulate --profile bad --out "$demo\syn-bad-seed6022" --seed 6022 --label "розетка-А"
uv run --python 3.12 lnt simulate --profile quiet --out "$demo\syn-quiet-seed6022" --seed 6022
uv run --python 3.12 lnt simulate --profile bad --out "$demo\series-a" --repeat 3 --interval 30 --label before
```

Первая команда завершается кодом 0 и выводит:

```text
Сессия записана: C:\Users\<пользователь>\AppData\Local\Temp\lnt-cli-demo\syn-bad-seed6022
```

Две первые сессии используются примерами дальше по тексту. Третья команда
снимает серию из трёх сессий с интервалом 30 секунд, это занимает около
минуты; печатается по строке `Сессия записана: …` на каждую сессию серии.

Идентификатор синтетической сессии строится как `syn-<профиль>-seed<семя>`,
например `syn-bad-seed6022`. Имя каталога может отличаться от идентификатора.

## `lnt capture`

Назначение: захват с Hantek 6022BE. Требует драйвер WinUSB, установка
описана в [руководстве оператора](operator-guide.md). Запись атомарна: байты
пишутся в каталог `.partial-*`, по завершении он переименовывается; прерванная
запись не оставляет половины сессии. Перед захватом выполняется preflight, его
проверки нельзя отключить.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--out` | путь | обязателен | каталог новой сессии |
| `--duration` | число, с | 2.4 | длительность записи |
| `--rate` | число, Гц | 8000000.0 | частота выборки |
| `--range` | `5.0`, `1.0`, `0.5` | 5.0 | диапазон CH1: полная шкала ±5.12 / ±1.024 / ±0.512 В |
| `--self-noise` | флаг | выкл | baseline самошума: фронтенды отключены, входы терминированы |
| `--line-quality` | флаг | выкл | качество сети 50 Гц: CH1 на вторичке трансформатора 230:6, одноканальный режим |
| `--probe-multiplier` | число | не задан, берётся 10 | коэффициент пробника для `--line-quality`, пробник 10x |
| `--baseline` | путь | не задан | явный каталог baseline-сессии самошума |
| `--rc-r-ohm` | число, Ом | не задан, берётся 100 | последовательный резистор RC-шунта |
| `--rc-c1-nf` | число, нФ | не задан, берётся 10 | C1 RC-шунта |
| `--rc-c2-nf` | число, нФ | не задан, берётся 10 | C2 RC-шунта |
| `--component-values-basis` | `nominal`, `operator_measured` | `nominal` | происхождение номиналов RC |
| `--termination-ohm` | число, Ом | не задан, берётся 50 | терминирование входа для `--self-noise` |
| `--probe-pair` | флаг | выкл | измерение CM/DM: щуп CH1 на L, щуп CH2 на N, только два канала |
| `--probe-pair-calibrate` | флаг | выкл | калибровка CM/DM: оба щупа на один проводник, только с `--probe-pair` |
| `--probe-calibration` | путь | не задан | каталог калибровочной сессии CM/DM, только с `--probe-pair` |
| `--channels` | `1`, `2` | 2 | см. `lnt simulate` |
| `--label` | текст | не задан | см. `lnt simulate` |
| `--repeat` | целое | 1 | см. `lnt simulate` |
| `--interval` | число, с | 0.0 | см. `lnt simulate` |

Без явных RC-флагов LNT фиксирует номинальную модель `100 Ом / 10 нФ /
10 нФ`. Baseline и основное измерение должны совпадать по источнику, частоте,
диапазону, пробнику и калибровке; вычитание baseline делает анализ, сырой
`spectrum.csv` он не меняет.

Правила режимов, нарушение даёт `InputError` и код 2:

- `--probe-pair-calibrate` и `--probe-calibration` требуют `--probe-pair`.
- `--probe-pair` несовместим с `--self-noise`, `--line-quality`,
  `--channels 1`, `--baseline`, `--termination-ohm`, `--probe-multiplier`
  и всеми RC-флагами.
- `--termination-ohm` допустим только с `--self-noise`.
- `--probe-multiplier` допустим только с `--line-quality`.
- `--self-noise` отвергает `--baseline` и измерительные флаги;
  `--line-quality` отвергает `--baseline`, RC-флаги и терминирование.
- RC-номиналы задаются полной тройкой `--rc-r-ohm` + `--rc-c1-nf` +
  `--rc-c2-nf`, и явная тройка не может использовать
  `--component-values-basis nominal`.

Коды выхода: 0 (успех); 2 (неверный вход или провал preflight); 3
(осциллограф недоступен или занят, в stderr печатается строка с префиксом
`Устройство:`).

Примеры:

```powershell
uv run --python 3.12 lnt capture --out "$demo\hw-001"
uv run --python 3.12 lnt capture --out "$demo\cmdm-001" --probe-pair --probe-calibration "$demo\cmdm-cal-001"
```

С подключённым осциллографом первая команда завершается кодом 0 и выводит:

```text
Сессия записана: C:\Users\<пользователь>\AppData\Local\Temp\lnt-cli-demo\hw-001
```

Аппаратная сессия получает схему манифеста v2 и идентификатор вида
`cap-<дата>-<hex>`. Без осциллографа та же команда завершается кодом 3.
Второй пример это режим CM/DM с явной калибровочной сессией.

## `lnt analyze`

Назначение: анализ сессии, пишет артефакты `metrics.json` и `spectrum.csv`,
а также `spectrum_input_referred.csv` и `spectrum_max_hold.csv`, когда
приведение доступно. Ветка выбирается по типу сессии: иголки и спектр, CM/DM
или качество сети; ветка качества сети пишет собственный набор артефактов и
отдельный отчёт.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `session` (позиционный) | путь | обязателен | каталог сессии |

Коды выхода: 0 (успех); 2 (битая или неподходящая сессия: `InputError`,
`AnalysisError`, отсутствующие файлы). Устройства нет, код 3 не встречается.

Пример:

```powershell
uv run --python 3.12 lnt analyze "$demo\syn-bad-seed6022"
uv run --python 3.12 lnt analyze "$demo\syn-quiet-seed6022"
```

Первая команда завершается кодом 0 и выводит:

```text
Сессия: syn-bad-seed6022
Источник: synthetic / measurement
Профиль: bad
Сеть: 50.00 Гц, циклов: 119
Запись: fs=500000 Гц, длительность 2.40 с
Иголки: mu_pk=0.1840 В, sigma/mu=0.205
Асинхронность: P_async/P_sync=0.468
Огибающая CH2: CV=0.0139
Пики спектра:
      22385 Гц    -68.3 дБ  Q=16.3  (пром. 24.7 дБ)
CH1 input-reference: unavailable (manifest_schema_v1)
Артефакты: metrics.json, spectrum.csv
```

Вторая сессия нужна примеру `lnt compare` ниже. Приведение CH1 ко входу для
синтетики схемы v1 недоступно, и это печатается явно, а не подменяется числом.

## `lnt ripple`

Назначение: риппл и шум сессии. Пишет аддитивный сайдкар `ripple.json` рядом
с сессией, существующие артефакты не трогает, вердиктов не выносит. Полоса
обязательна: тихого значения по умолчанию нет.

Аргумент сессии принимает прямой путь, имя каталога или `session_id`; прямой
путь приоритетнее, иначе имя разрешается под `--root`.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `session` (позиционный) | путь, имя или идентификатор | обязателен | сессия |
| `--root` | путь | `~/lnt-sessions` | корень для разрешения имени или `session_id` |
| `--band-low` | число, Гц | обязателен | нижняя граница полосы, `>= 0`, DC-бин исключён |
| `--band-high` | число, Гц | обязателен | верхняя граница полосы, `<= fs/2` сессии |
| `--cap-nf` | число, нФ | декларация контекста, иначе 100 | ёмкость последовательного конденсатора адаптера |
| `--series-r-ohm` | число, Ом | декларация, иначе 0 | последовательный резистор адаптера |
| `--probe` | `1x`, `10x` | декларация, иначе `1x` | объявленный пробник адаптера: проверка равенства с манифестом, не пересчёт |
| `--window-s` | число, с | 1.0 | окно интервалов time-domain |
| `--preconnected` | флаг | декларация, иначе `settling_unknown` | операторское объявление: подключение до старта записи, без переподключений в эпохе |
| `--baseline` | путь | не задан | каталог фоновой сессии; публикуется рядом, не вычитается |
| `--baseline-shorted-tip` | флаг | выкл | объявление условия фона: наконечник адаптера замкнут на возврат той же сборки; требует `--baseline` |

Флаги адаптера читают декларацию контекста сессии, когда не заданы. Заданный
флаг это утверждение против декларации: расхождение даёт код 2.

Коды выхода: 0 (успех); 1 (внутренняя ошибка движка, одна строка в stderr
без трейсбека); 2 (неверная полоса, нечитаемая сессия,
`--baseline-shorted-tip` без `--baseline`, расхождение с декларацией).

Примеры:

```powershell
uv run --python 3.12 lnt ripple syn-bad-seed6022 --root $demo --band-low 100 --band-high 20000
uv run --python 3.12 lnt ripple "$demo\cmdm-001" --band-low 1000 --band-high 100000 --baseline "$demo\bg-001" --baseline-shorted-tip
```

Первая команда завершается кодом 0 и выводит:

```text
ripple: time: недоступно (settling_unknown); полоса 100-20000 Гц: недоступно (settling_unknown); спан 2.4 с; фон: нет; полоса запрошена 100-20000 Гц
Сайдкар: ripple.json
```

Сессия без декларации адаптера не даёт чисел: состояние подключения неизвестно,
величины печатаются недоступными. С явной декларацией:

```powershell
uv run --python 3.12 lnt ripple syn-bad-seed6022 --root $demo --band-low 100 --band-high 20000 --cap-nf 100 --series-r-ohm 0 --probe 1x --preconnected
```

```text
ripple: time: mean=-6.7212e-06 В, rms_ac=0.017822 В, vpp=0.62982 В; полоса 100-20000 Гц: rms=0.0059457 В (19901 бинов); спан 1.4 с; фон: нет; полоса запрошена 100-20000 Гц
Сайдкар: ripple.json
```

Спан 1,4 с из 2,4: политика сеттлинга отбрасывает первые `10 * tau`, с
декларацией из примера это 1,0 с. Второй пример показывает форму вызова с
фоновой сессией.

## `lnt compare`

Назначение: таблица дельт двух сессий, дельта считается как `B - A`.

Быстрый путь читает `metrics.json` и `spectrum.csv` каждой сессии, поэтому
сначала нужен `lnt analyze`. Если артефактов нет или они битые, делается
полный анализ, коды выхода сохраняются.

Точность: `spectrum.csv` хранит PSD в формате `%.9g`, дельты последних знаков
могут отличаться от полного пересчёта; рендер CLI с шагом 0,1 дБ совпадает
побитово.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `session_a` (позиционный) | путь | обязателен | сессия A, база |
| `session_b` (позиционный) | путь | обязателен | сессия B |

Коды выхода: 0 (успех); 2 (битые сессии, в том числе через откат на полный
анализ).

Пример:

```powershell
uv run --python 3.12 lnt compare "$demo\syn-bad-seed6022" "$demo\syn-quiet-seed6022"
```

Код 0, вывод:

```text
Сравнение: A=syn-bad-seed6022  B=syn-quiet-seed6022
Пики спектра (дельта = B - A):
     частота     A, дБ     B, дБ   дельта  Q A->B
     22385 Гц     -68.3     -96.0    -27.7  16.3 -> 17.1
Метрики иголок:
  needle_mean_v           0.18402 ->    0.01199  (-93.5%)  дельта -0.17202
  needle_sigma_ratio      0.20467 ->    0.11652  (-43.1%)  дельта -0.08814
  async_sync_ratio        0.46775 ->    4.81203  (+928.8%)  дельта +4.34428
  lf_envelope_cv          0.01395 ->    0.00483  (-65.4%)  дельта -0.00912
```

## `lnt ui`

Назначение: локальный веб-дашборд. Слушает только `127.0.0.1`, внешний доступ
невозможен. Нужен extra `ui`, его установка описана в [README](../README.md).
Работает один экземпляр: аппаратная аренда, второй запуск завершается
кодом 2, пока живёт первый.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--root` | путь | `~/lnt-sessions` | корень сессий, создаётся при отсутствии |
| `--port` | целое | 8765 | порт, от 1 до 65535 |
| `--no-browser` | флаг | выкл | не открывать браузер автоматически |

Коды выхода: 0 (штатная остановка, `Ctrl+C` тоже 0); 2 (порт вне диапазона,
занятый порт, второй экземпляр, отсутствие зависимостей extra `ui`, прочий
`InputError`).

Примеры:

```powershell
uv run --python 3.12 lnt ui
uv run --python 3.12 lnt ui --root $demo --port 8800 --no-browser
```

Браузер открывается на `http://127.0.0.1:8765/`. Остановка: `Ctrl+C` в консоли,
код 0.

Запуск второго экземпляра при живом первом завершается кодом 2 и одной
строкой в stderr, значения PID и метки времени зависят от запуска:

```text
Ошибка: аппарат уже занят: PID=19800, запуск=134373079870933010, сборка=5a9b8bd3b7656f5f, получено=2026-10-24T09:33:08.397348+00:00
```

Назначение: экспорт, backup и restore сессий с проверкой контрольных сумм

Примеры ниже используют две сессии из разделов `simulate`, `analyze` и
`ripple`: по 9 файлов на сессию после анализа плюс сайдкар `ripple.json` у

## `lnt catalog`

Назначение: обслуживание каталога сессий. Каталог это перестраиваемая
SQLite-проекция поверх сессий на диске: сессии остаются источником истины,
починка всегда `reindex`, ручные правки БД запрещены. БД по умолчанию живёт в
`%LOCALAPPDATA%\LNT\catalog.sqlite3`; флаг `--database` у операций группы
перенаправляет её. Примеры ниже используют БД внутри `$demo`, чтобы не трогать
каталог по умолчанию.

### `lnt catalog status`

Назначение: состояние каталога и health-счётчики, плюс время последней
сверки.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--database` | путь | `%LOCALAPPDATA%\LNT\catalog.sqlite3` | путь БД каталога |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (успех); 2 (проблемы каталога).

Пример:

```powershell
uv run --python 3.12 lnt catalog status --database "$demo\catalog.sqlite3"
```

Код 0, вывод, значения зависят от корня и времени сверки:

```text
Здоровье каталога: ok=2
Последняя сверка: {'root_path': 'C:\\Users\\<пользователь>\\AppData\\Local\\Temp\\lnt-cli-demo', 'completed_utc': '2026-10-24T10:59:54.084Z', 'scanned': 2, 'changed': 2, 'deleted': 0}
```

### `lnt catalog reindex`

Назначение: полная перестройка проекций каталога по сессиям на диске.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--root` | путь | обязателен | корень сессий |
| `--database` | путь | `%LOCALAPPDATA%\LNT\catalog.sqlite3` | путь БД каталога |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (успех); 2 (неверный вход).

Пример:

```powershell
uv run --python 3.12 lnt catalog reindex --root $demo --database "$demo\catalog.sqlite3" --json
```

Код 0, вывод (две сессии из примеров; если вы делали захват или серию,
счётчики будут больше):

```text
{"deleted": 0, "inserted": 2, "scanned": 2, "skipped": 0, "updated": 0}
```

### `lnt catalog verify`

Назначение: сверка каталога с диском без записи. При расхождении печатает
`Обнаружено расхождение каталога:` и список путей, по одному на строку.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--root` | путь | обязателен | корень сессий |
| `--database` | путь | `%LOCALAPPDATA%\LNT\catalog.sqlite3` | путь БД каталога |
| `--deep` | флаг | выкл | хешировать содержимое raw-файлов, медленнее, ловит смену байтов |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (расхождений нет); 1 (расхождение найдено); 2 (неверный
вход). Лечится расхождение командой `reindex`.

Пример:

```powershell
uv run --python 3.12 lnt catalog verify --root $demo --database "$demo\catalog.sqlite3"
```

Код 0, вывод:

```text
Расхождений каталога нет
```

Назначение: безопасный просмотр legacy-сайдкара `context.legacy.json`.

| `--dry-run` | флаг | обязателен | всегда сухой прогон |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (успех); 2 (каталога нет, `context.legacy.json` не найден или

Пример:

```powershell
uv run --python 3.12 lnt catalog import-context "$env:TEMP\lnt-legacy-001" --dry-run --json
```

## `lnt sessions`

Назначение: запросы каталога сессий. Команды группы читают каталог по
умолчанию, флага `--database` у них нет. Каталог наполняется запуском `lnt ui`
или командой `lnt catalog reindex` без `--database`.

### `lnt sessions list`

Назначение: страница каталога сессий с фильтрами.

| Флаг | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `--health` | `ok`, `corrupt_manifest`, `missing_files`, `partial`, `duplicate_id`, `context_invalid`, `analysis_invalid` | не задан, все | фильтр по health |
| `--session-type` | строка | не задан | фильтр по типу, например `measurement`, `self_noise`, `line_quality`, `cm_dm` |
| `--source` | строка | не задан | фильтр по источнику, например `device`, `synthetic` |
| `--profile` | строка | не задан | фильтр по профилю сигнала |
| `--label` | строка | не задан | фильтр по метке |
| `--tag` | строка | не задан | фильтр по метке контекста |
| `--page-size` | целое | 50 | размер страницы, от 1 до 200, иначе код 2 |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (успех); 2 (`--page-size` вне диапазона, проблемы каталога).

Примеры:

```powershell
uv run --python 3.12 lnt sessions list
uv run --python 3.12 lnt sessions list --health ok --json --page-size 200
```

Вывод печатает идентификатор и health каждой сессии страницы; `--json` даёт
машинночитаемую форму. Содержимое зависит от вашего каталога.

## `lnt context`

Назначение: контекст сессии: метки, заметки, снимки профилей. Ревизии
защищены optimistic-конкуренцией: `--expected-revision` обязан равняться
текущей ревизии. Сессия разрешается через каталог по умолчанию.

### `lnt context show`

Назначение: снимок контекста сессии.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `session_id` (позиционный) | идентификатор | обязателен | сессия, разрешается через каталог |
| `--json` | флаг | выкл | машиночитаемый вывод |

Коды выхода: 0 (успех); 2 (сессия не найдена).

Пример:

```powershell
uv run --python 3.12 lnt context show syn-bad-seed6022 --json
```

Печатает версию схемы, `session_id`, ревизию, поля, снимки профилей, метки и
заметки. Пример ниже по `context set` предполагает ревизию 1: столько держит
свежая синтетическая сессия.

### `lnt context set`

Назначение: обновление меток и заметок с защитой ревизии.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `session_id` (позиционный) | идентификатор | обязателен | сессия, разрешается через каталог |
| `--expected-revision` | целое | обязателен | текущая ревизия; не равна, код 2 |
| `--tag` | строка | пусто, метки сохраняются | метки, повторяется |
| `--notes` | текст | не задан, заметки сохраняются | заметки оператора |

Коды выхода: 0 (успех); 2 (сессия не найдена, конфликт ревизии).

Примеры, сессия проиндексирована в каталоге по умолчанию командой
`lnt catalog reindex --root $demo` без `--database`:

```powershell
uv run --python 3.12 lnt context set syn-bad-seed6022 --expected-revision 1 --tag after --notes "замена блока питания"
uv run --python 3.12 lnt context set syn-bad-seed6022 --expected-revision 2 --notes "перепроверка"
```

Первая команда завершается кодом 0 и выводит:

```text
Контекст обновлён: revision 2
```

Повторный запуск с устаревшей ревизией завершается кодом 2:

```text
Ошибка: конфликт revision контекста: ожидалась 1, текущая 2
```

### `lnt experiment trends`

Назначение: ограниченный продольный анализ тренда по файлу запроса,
эквивалент `TrendQuery` API: наблюдения с временными метками, предиктором и
исходом, `minimum_n`, `max_lag`, `bootstrap_samples`, `seed`, `units`. Файл
примера в приложении.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `value` (позиционный) | путь | обязателен | JSON-файл параметров тренда |
| `--root` | путь | `~/lnt-sessions` | корень сессий |

Коды выхода: 0 (успех); 2 (нечитаемый или некорректный файл).

Пример:

```powershell
uv run --python 3.12 lnt experiment trends "$demo2\trend-params.json" --root "$demo2\sessions"
```

Код 0. Вывод это JSON с секциями `trends`, `correlations`, `data_quality` и
`metadata`; все результаты помечены `descriptive_exploratory`, корреляции
печатаются с интервалами и поправкой множественных сравнений
`benjamini_hochberg`, конфаундеры дают предупреждение «наблюдаемые факторы
могут совместно изменяться». Метаданные примера:

```text
  "metadata": {
    "units": "s",
    "estimator": "descriptive_longitudinal",
    "n": 5,
    "provenance": {
      "seed": 3,
      "dedupe_policy": "keep_first_by_input_order"
    }
  }
```

### `lnt experiment check`

Назначение: проверка сопоставимости каждой смежной пары членов эксперимента.
Находки печатаются; заблокированная сопоставимость видна в выводе, не в коде
выхода.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `value` (позиционный) | идентификатор | обязателен | идентификатор эксперимента |
| `--root` | путь | `~/lnt-sessions` | корень сессий |

Коды выхода: 0 (успех); 2 (эксперимент не найден, у члена нет или битый
`comparability.json`).

Пример:

```powershell
uv run --python 3.12 lnt experiment check latency-study --root "$demo2\sessions"
```

Член `session-a` из примера не имеет `comparability.json`, команда завершается
кодом 2 и строкой:

```text
Ошибка: сопоставимость: не удалось прочитать C:\Users\<пользователь>\AppData\Local\Temp\lnt-cli-exp\sessions\session-a\comparability.json: [Errno 2] No such file or directory: 'C:\\Users\\<пользователь>\\AppData\\Local\\Temp\\lnt-cli-exp\\sessions\\session-a\\comparability.json'
```

### `lnt experiment confirm`

Назначение: подтверждение прогона протокола как реального вмешательства с
аудируемым актором. Хранилище прогонов живёт в `<root>/../protocol-runs`.

| Флаг/аргумент | Аргумент | По умолчанию | Что делает |
|---|---|---|---|
| `value` (позиционный) | идентификатор | обязателен | идентификатор прогона протокола |
| `--actor` | текст | обязателен | имя подтверждающего оператора |
| `--root` | путь | `~/lnt-sessions` | корень сессий |

Коды выхода: 0 (успех); 2 (прогон не найден, неверный вход).

Пример:

```powershell
uv run --python 3.12 lnt experiment confirm run-018f6a2e --actor "K. Ivanov"
```

## `lnt hypothesis`

Назначение: аудируемые гипотезы. `--root` задаёт корень сессий, гипотезы

правки задним числом: каждая правка это явная следующая ревизия, журнал
append-only.

### `lnt hypothesis add`

Назначение: регистрация гипотезы из JSON-файла, ожидается ревизия 0.

| `--root` | путь | `~/lnt-sessions` | корень сессий |

Коды выхода: 0 (успех); 2 (нечитаемый или некорректный файл).

Пример:

```powershell
uv run --python 3.12 lnt hypothesis add "$demo2\hyp-001.json" --root "$demo2\sessions"
```

Код 0, вывод:

```text
Гипотеза сохранена: lower-latency
```

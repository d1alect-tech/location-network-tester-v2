# Установка LNT на Windows

LNT ставится из исходников: `git clone` и uv. Всё исполнимое живёт в каталоге
репозитория и его окружении `.venv`, глобально в систему ничего не
устанавливается. Данные приложения лежат вне репозитория — где именно,
см. раздел «Первый запуск и каталог сессий».

Готовая переносная сборка, которой не нужны ни git, ни Python, ни uv,
описана в [agent-setup.md](agent-setup.md) и на
[странице релизов](https://github.com/d1alect-tech/location-network-tester-v2/releases).
Этот документ — про установку из исходников.

Все команды выполняются в PowerShell из корня репозитория. Каждая команда
LNT запускается в форме `uv run --python 3.12 lnt ...` — Python 3.12 это
рабочая версия проекта, и она указывается явно.

## Предварительные требования

| Компонент | Требование | Зачем нужен |
|---|---|---|
| Windows | 64-бит | единственная поддерживаемая платформа |
| [uv](https://docs.astral.sh/uv/) | версия не запинена | ставит Python и зависимости, запускает `lnt` |
| Python | `>=3.12`, рабочий стандарт проекта — 3.12 | `requires-python` из `pyproject.toml`; ruff и basedpyright настроены на 3.12 |
| git | версия не запинена | клонирование репозитория |
| Node.js + npm | версия не запинена (`engines` в `frontend/package.json` отсутствует) | только для пересборки фронтенда, для запуска LNT не нужен |

Python отдельно ставить не обязательно: uv скачивает управляемый Python 3.12
сам при первом `uv sync --python 3.12`. Минимальные версии Windows, uv и git,
на которых всё заведётся, недоступны — не выдумываются; ставьте актуальные.

Пакет: `lnt`, версия 0.1.2, лицензия GPL-3.0-only. Базовые зависимости,
ставятся всегда: `numpy>=2.1,<3` и `scipy>=1.14,<2`.

## Установка

```powershell
git clone https://github.com/d1alect-tech/location-network-tester-v2.git
cd location-network-tester-v2
uv sync --python 3.12 --extra ui
```

`uv sync` создаёт `.venv` в корне репозитория и ставит туда пакет `lnt`,
базовые зависимости, группу разработки (pytest, ruff 0.16.1, basedpyright
1.39.9 и другие инструменты — это ожидаемо) и выбранные extras. Команда `lnt`
глобально не устанавливается: запускайте её в форме
`uv run --python 3.12 lnt ...` из корня репозитория.

### Extras

| Extra | Что ставит | Назначение |
|---|---|---|
| `ui` | `fastapi==0.140.0`, `python-multipart==0.0.32`, `uvicorn==0.51.0` | веб-интерфейс `lnt ui`; без него `lnt ui` завершается с кодом 2 и подсказкой в stderr |
| `hantek` | `hantek6022api` из git, коммит `e65d52b0f2536e56eaadbb555e5d7b756409c36e` | драйвер Hantek 6022BE для настоящего захвата; git-зависимость с GitHub, при sync нужен доступ к сети |

Для настоящих измерений ставьте оба extras одной командой:

```powershell
uv sync --python 3.12 --extra ui --extra hantek
```

`uv sync` приводит окружение точно к запрошенному набору: повторный запуск с
другим набором extras удалит прежний. Флаг `--extra` можно указывать
несколько раз, есть сокращение `--all-extras`. Если после установки драйвера
пропал веб-интерфейс — вы пересинхронизировались без `--extra ui`; повторите
sync со всеми нужными extras.

## Проверка установки

Пять шагов, каждый проверяется кодом выхода и видимым результатом. При тех же
аргументах вывод повторяется; частота пика может отличаться на несколько герц
на другой машине, поэтому ориентир — структура отчёта и код выхода, а не
отдельные цифры.

### Справка

```powershell
uv run --python 3.12 lnt --help
```

Ожидаемый вывод (начало; перенос длинных строк зависит от ширины консоли):

```text
usage: lnt [-h]
           {archive,sessions,context,profiles,reindex,experiment,hypothesis,simulate,capture,analyze,ripple,compare,ui,support-bundle,selftest,catalog}
           ...

Location Network Tester: захват и анализ сетевых помех (Hantek 6022BE)

positional arguments:
  {archive,sessions,context,profiles,reindex,experiment,hypothesis,simulate,capture,analyze,ripple,compare,ui,support-bundle,selftest,catalog}
    archive             проверенные экспорт, backup и restore
    ...
```

Код выхода 0. Этот список подкоманд — вся поверхность CLI: `simulate`,
`capture`, `analyze`, `ripple`, `compare`, `ui`, `selftest`, `catalog`,
`archive` и исследовательские команды.

### Версия

Флага `--version` у CLI нет. Команда ниже завершается с кодом 2 и одной
строкой в stderr — это ожидаемое поведение, а не сбой установки:

```powershell
uv run --python 3.12 lnt --version
```

```text
Ошибка: аргументы: the following arguments are required: command
```

Номер версии пакета — 0.1.2, из `pyproject.toml` и имён релизных архивов
(`LNT-0.1.2-win64.zip`). Работающий интерфейс сообщает свою сборку в
`/api/health`, поле `build_id` вида `0.1.2+<хеш>`.

### Самопроверка

```powershell
uv run --python 3.12 lnt selftest
```

```text
SELFTEST OK: пик 22385 Гц, циклов 119
```

Код 0. Команда прогоняет тракт «синтетика → анализ» целиком; USB-устройство
и драйвер она не задействует. Провал — код 1 и одна строка в stderr.

### Симуляция и анализ

Проверка идёт во временном каталоге, репозиторий не затрагивается:

```powershell
$demo = "$env:TEMP\lnt-smoke"
uv run --python 3.12 lnt simulate --profile bad --out "$demo\syn-bad-seed6022" --seed 6022 --label "розетка-А"
```

```text
Сессия записана: C:\Users\<имя>\AppData\Local\Temp\lnt-smoke\syn-bad-seed6022
```

Код 0. Затем анализ:

```powershell
uv run --python 3.12 lnt analyze "$demo\syn-bad-seed6022"
```

```text
Сессия: syn-bad-seed6022
Источник: synthetic / measurement
Профиль: bad
Сеть: 50.00 Гц, циклов: 119
Запись: fs=500000 Гц, длительность 2.40 с
Иголки: mu_pk=0.1840 В, sigma/mu=0.205
Асинхронность: P_async/P_sync=0.468
Огибающая CH2: CV=0.0139
Пики спектра:
      22385 Гц    -68.3 дБ  Q=16.3  (пром. 24.7 дБ)
CH1 input-reference: unavailable (manifest_schema_v1)
Артефакты: metrics.json, spectrum.csv
```

Код 0. Что анализ действительно записал артефакты, проверяется по файлам:

```powershell
Test-Path "$demo\syn-bad-seed6022\metrics.json", "$demo\syn-bad-seed6022\spectrum.csv"
```

```text
True
True
```

Профили симуляции: `bad`, `bad-damped` (тот же пик на 22,4 кГц, но на 12 дБ
ниже), `quiet`, `sync-only`, `async-heavy`. Сделайте вторую сессию другим
профилем, откройте «Инспекцию» и сравните их — это рабочий цикл LNT, только
с синтетикой вместо настоящих записей.

### Веб-интерфейс

```powershell
uv run --python 3.12 lnt ui --root $demo
```

```text
LNT UI: http://127.0.0.1:8765/
```

Следом в консоль пишутся служебные строки uvicorn. Браузер открывается сам
после того, как `/api/health` ответит (ожидание до 30 секунд); если браузер
не открылся, откройте адрес руками — сервер от этого не зависит. Флаг
`--no-browser` отключает автозапуск браузера. Остановка — Ctrl+C, код
выхода 0.

Пока интерфейс запущен, второй `lnt ui` завершится с кодом 2 — см. раздел
«Один экземпляр и порты».

Каталог проверки можно удалить:

```powershell
Remove-Item $demo -Recurse -Force
```

### Коды выхода

| Код | Значение |
|---|---|
| 0 | команда выполнена |
| 1 | selftest не прошёл |
| 2 | неверные аргументы, повреждённые данные, занятый порт, второй экземпляр, отсутствует extra `ui` |
| 3 | устройство недоступно (драйвер или USB) |

Пользовательская ошибка печатается одной строкой в stderr, без traceback.

## Драйвер Hantek для настоящих измерений

Без драйвера LNT полностью работает на синтетике: `simulate`, `analyze`,
`compare`, `catalog` и веб-интерфейс. Драйвер нужен только команде `capture`
и экрану захвата в UI.

Импорт драйвера ленивый: `PyHT6022.LibUsbScope.Oscilloscope` загружается
внутри `open_real_scope()` в момент первого реального захвата. Если extra
не установлен, захват завершается с кодом 3 и одной строкой в stderr:

```text
Устройство: драйвер hantek6022api не установлен: pip install 'lnt[hantek]' (см. README)
```

Что ставит пользователь:

1. Python-часть: `uv sync --python 3.12 --extra ui --extra hantek`.
2. `libusb-1.0.dll` — рядом с `python.exe` окружения, то есть в
   `location-network-tester-v2\.venv\Scripts\`.
3. WinUSB через [Zadig](https://zadig.akeo.ie/): подключите осциллограф,
   запустите Zadig, включите `Options` → `List All Devices`, выберите
   устройство с VID `04B4` и установите для него WinUSB. Zadig в поставку
   LNT не входит и автоматически не скачивается.
4. После первого захвата прошивка устройства меняет VID с `04B4` на `04B5`,
   и оно «пропадает» из списка устройств. Это ожидаемое поведение: поставьте
   WinUSB ещё раз для нового VID.
5. Проверка: `uv run --python 3.12 lnt selftest`. Она проверяет тракт
   синтетики и анализа; USB-канал проверяется первым настоящим захватом.

Лицензия: Hantek6022API распространяется под GPL-3.0-only, как и сам LNT.
Версия драйвера закреплена коммитом `e65d52b0f2536e56eaadbb555e5d7b756409c36e`
(2026-04-22) — версия, чья API-поверхность верифицирована. В базовую
установку драйвер не входит и попадает в окружение только через extra
`hantek`: железо опционально, тесты и работа на синтетике устройство
не требуют.

Полная инструкция с картинками и разбором отказов —
[руководство оператора](operator-guide.md).

## Первый запуск и каталог сессий

Без флагов `lnt ui` работает с каталогом `~\lnt-sessions`, то есть
`C:\Users\<имя>\lnt-sessions`. Каталог из `--root` создаётся автоматически,
руками создавать не нужно.

`--root` меняет только место, где живут сессии. Служебные данные остаются
на своих местах:

| Что | Где |
|---|---|
| сессии по умолчанию | `C:\Users\<имя>\lnt-sessions` |
| конфигурация | `%APPDATA%\LNT\config.json` |
| индекс каталога сессий | `%LOCALAPPDATA%\LNT\catalog.sqlite3` |
| runtime и блокировка экземпляра | `%LOCALAPPDATA%\LNT\runtime.sqlite3`, `%LOCALAPPDATA%\LNT\hardware.lease` |
| журнал, кэш, данные поддержки | подкаталоги `%LOCALAPPDATA%\LNT` |

Флаги `lnt ui`:

| Флаг | По умолчанию | Действие |
|---|---|---|
| `--root DIR` | `~\lnt-sessions` | каталог сессий |
| `--port N` | `8765` | порт на 127.0.0.1 |
| `--no-browser` | выключено | не открывать браузер автоматически |

API находит сессию и по имени каталога, и по `session_id` из
`manifest.json` (у синтетики — `syn-<профиль>-seed<семя>`), поэтому имя
каталога может отличаться от идентификатора — сессия всё равно откроется.

## Один экземпляр и порты

Интерфейс слушает `127.0.0.1:8765` и только loopback: из локальной сети
сервер недоступен, Swagger и ReDoc выключены. Второй экземпляр на той же
машине не запускается — так устроен сервер: единый менеджер заданий и
единственный владелец USB-устройства.

Второй `lnt ui` при живом первом завершается с кодом 2 и одной строкой
(числа — сведения о первом экземпляре):

```text
Ошибка: аппарат уже занят: PID=19800, запуск=…, сборка=…, получено=…
```

Что делать: остановить первый экземпляр — Ctrl+C в его консоли, код выхода
будет 0. Файл блокировки — `%LOCALAPPDATA%\LNT\hardware.lease`; если владелец
уже мёртв, следующая копия вытесняет его автоматически, вручную файл удалять
не нужно.

Занятый порт — отдельный случай: `lnt ui` из репозитория биндит ровно
указанный порт, подбора соседнего нет. Если 8765 занят другим процессом:

```text
Ошибка: порт 127.0.0.1:8765 уже занят другим сервером
```

Код 2. Освободите порт — остановите первый экземпляр или процесс, который
его занял, — либо укажите другой порт. Кто держит порт:

```powershell
Get-NetTCPConnection -LocalPort 8765 | Select-Object OwningProcess, State
```

Релизная сборка ведёт себя иначе: сама выбирает первый свободный порт
диапазона 8765..8780, а при живом экземпляре подключается к нему. На запуск
из репозитория это не влияет — действует порт из `--port` и только он.

Проверить, что уже запущено, можно без браузера:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

Ответ: `status` = `ok`, `build_id` вида `0.1.2+<хеш>`.

## Обновление

```powershell
git pull
uv sync --python 3.12 --extra ui
```

Если ставили драйвер — повторите sync со всеми extras:

```powershell
uv sync --python 3.12 --extra ui --extra hantek
```

`uv sync` не сохраняет прежний набор extras, поэтому флаги повторяются
полностью. Собранный фронтенд уже лежит в репозитории
(`src/lnt/ui/static/v2`): пересборка через npm нужна только тем, кто меняет
код фронтенда. Каталог сессий и данные приложения находятся вне репозитория,
`git pull` их не затрагивает.

## Удаление

1. Остановите интерфейс, если запущен: Ctrl+C в его консоли.
2. Удалите каталог репозитория — в нём весь исполняемый код и окружение
   `.venv`.
3. Удалите данные приложения:

   ```powershell
   Remove-Item -Recurse -Force "$env:APPDATA\LNT", "$env:LOCALAPPDATA\LNT"
   ```

4. Сессии удалите отдельно, если записи больше не нужны:

   ```powershell
   Remove-Item -Recurse -Force "$env:USERPROFILE\lnt-sessions"
   ```

Больше ничего LNT не пишет. uv и скачанный им Python — инструменты uv; если
ставили их только ради LNT, удаляйте средствами uv, см.
[документацию](https://docs.astral.sh/uv/).

## Частые ошибки установки

| Симптом | Причина | Лечение |
|---|---|---|
| `uv : имя "uv" не распознано…` | uv не установлен, либо терминал открыт до установки | `winget install --id=astral-sh.uv -e`, затем открыть новый терминал; другие способы — [документация uv](https://docs.astral.sh/uv/) |
| uv не находит или не скачивает Python 3.12 | отключена автозагрузка Python или нет доступа к сети | `uv python install 3.12` — ставит управляемый Python явно; по умолчанию uv скачивает его сам |
| `имя "git" не распознано…` при clone | git не установлен | `winget install --id Git.Git -e`, затем открыть новый терминал |
| `Ошибка: порт 127.0.0.1:8765 уже занят другим сервером`, код 2 | порт занят другим процессом | `Get-NetTCPConnection -LocalPort 8765` — найти PID, остановить процесс или запустить `uv run --python 3.12 lnt ui --port 8766 --root <DIR>` |
| `Ошибка: аппарат уже занят: PID=…`, код 2 | уже запущен другой экземпляр LNT | остановить его: Ctrl+C в его консоли; мёртвый PID вытесняется автоматически |
| `Ошибка: интерфейс не установлен: pip install 'lnt[ui]' (см. README)`, код 2 | `uv sync` выполнен без `--extra ui` | `uv sync --python 3.12 --extra ui` (добавьте `--extra hantek`, если нужен драйвер) |
| `Устройство: драйвер hantek6022api не установлен…`, код 3 | нет extra `hantek` при попытке захвата | `uv sync --python 3.12 --extra ui --extra hantek`, затем шаги Zadig из раздела про драйвер |
| русские строки в консоли — кракозябры | кодовая страница консоли | код выхода и ASCII-префиксы (`SELFTEST OK`, `LNT UI:`) читаются всегда; сами файлы остаются корректным UTF-8 |

# Руководство по веб-интерфейсу LNT

Этот документ проходит веб-панель LNT по вкладкам: что делает каждая вкладка,
типовой сценарий по шагам, ключевые контролы и их опции, ограничения и
состояния ошибок. Примеры привязаны к состоянию сразу после «Быстрого старта»
из [README](../README.md): две симулированные сессии, осциллограф не подключён.

Интерфейс русский и полностью офлайн: сервер слушает только `127.0.0.1`,
внешних сетевых запросов панель не делает. Команды ниже приведены для
PowerShell.

## Что интерфейс показывает, а что нет

LNT показывает измеренное значение и его фактическое сравнение с настроенным
пределом, и ничего сверх этого. Оценочных слов рядом с метриками панель не
пишет: решение остаётся за оператором. Отсутствующие данные показываются как
«н/д»: недоступно, не выдумывается. Заявлений о калиброванном напряжении,
аттестации и причинных выводах («из-за этой помехи лаг») в интерфейсе нет и
не появится. Подписи честные: отсчёты 8-битного АЦП, перевод в вольты живёт в
одном модуле проекта (`lnt.adc_calibration`), живые риппл-числа помечены как
некалиброванные вольты.

## Исходное состояние: быстрый старт

Проделайте быстрый старт из README и добавьте вторую сессию другим профилем:

```powershell
$demo = "$env:USERPROFILE\lnt-demo"
uv run --python 3.12 lnt simulate --profile bad --out "$demo\syn-bad-seed6022" --seed 6022 --label "розетка-А"
uv run --python 3.12 lnt analyze "$demo\syn-bad-seed6022"
uv run --python 3.12 lnt simulate --profile quiet --out "$demo\syn-quiet-seed6023" --seed 6023 --label "розетка-Б"
uv run --python 3.12 lnt analyze "$demo\syn-quiet-seed6023"
uv run --python 3.12 lnt ui --root $demo
```

Ожидаемый результат: браузер открывается на `http://127.0.0.1:8765/`, в
каталоге две проанализированные сессии. API находит сессию и по имени
каталога, и по идентификатору из манифеста: у синтетики это
`syn-<профиль>-seed<семя>`, каталог показывает именно идентификатор.

Синтетика имеет известную истину. У профиля `bad` иголки с амплитудой 0,2 В и
затухающий звон на 22,4 кГц; у `quiet` иголки 0,01 В с тем же звоном. Отношение
амплитуд 20:1, поэтому пик на 22,4 кГц у `bad` примерно на 26 дБ выше. Эти
числа дальше используются как ориентир в «Инспекции».

Второй запуск `lnt ui` при живом первом завершается с кодом 2: панель обязана
быть одна. Остановите первый экземпляр (Ctrl+C в его окне консоли) и освободите
порты 8765 и 8770.

## Оболочка

Навигация живёт в таб-баре с восемью вкладками:

| # | Вкладка | Маршрут | Подзаголовок раздела |
|---|---------|---------|----------------------|
| 1 | Каталог | `#/catalog` | Поиск и фильтрация сессий, инспектор контекста, управление профилями. |
| 2 | Захват | `#/capture` | Запуск одиночных или серийных измерений, отображение активной задачи. |
| 3 | Осциллограф | `#/scope` | Живой режим развёртки: непрерывный поток кадров, Run/Stop и статус владения прибором. |
| 4 | Спектроанализатор | `#/sa` | Живые трассы спектра: clear-write, min/max-hold и бегущее среднее; полоса и RBW на ходу. |
| 5 | Инспекция | `#/inspect` | Детальный анализ выбранной сессии, просмотр спектра мощности (PSD). |
| 6 | Эксперименты | `#/experiments` | Группировка сессий по протоколам (A/B, A/B/A, повторные серии). |
| 7 | Отчёты | `#/reports` | Генерация научных отчетов с полной прослеживаемостью (provenance). |
| 8 | Настройки | `#/settings` | Управление путями сессий, базами данных, резервным копированием. |

Прочее по оболочке:

- Хэш-маршрутизация: пустой или неизвестный hash уводит на `#/catalog`.
- Шапка: слева бренд «LNT», справа поле статуса устройства с текстом по
  умолчанию «устройство · готов». Фактическое состояние прибора с причиной и
  следующим действием показывают панели устройства: шаг 3 «Захвата», командбар
  «Инспекции», диагностика «Настроек».
- Статусбар внизу: «готов» и «Корень: …».
- При смене вкладки экранный диктор объявляет название раздела.
- Уход с вкладок «Осциллограф» и «Спектроанализатор» останавливает живой
  захват (`POST /api/live/stop`), если панель считала его активным.
- Критическая ошибка интерфейса: панель «Критическая ошибка интерфейса» с
  текстом ошибки и кнопкой «Сбросить и вернуться на главную» (возврат в
  каталог).

## 1. Каталог

**Что делает.** Поиск и фильтрация сохранённых сессий, просмотр и правка
контекста выбранной сессии, управление профилями измерений. Раскладка: слева
панель каталога (тулбар фильтров и плотная таблица), справа вкладки
«Инспектор» и «Профили».

**После быстрого старта.** В списке две сессии: `syn-bad-seed6022`
(«розетка-А») и `syn-quiet-seed6023` («розетка-Б»). Правая панель ждёт выбора:
клик по строке открывает контекст сессии в «Инспекторе».

**Типовой сценарий.**

1. Откройте «Каталог»: это маршрут по умолчанию.
2. Введите «розетка» в поле «Метка». Список перезапрашивается с паузой 150 мс
   после ввода; значения фильтров живут в параметрах URL и переживают
   перезагрузку страницы.
3. Кликните строку сессии. «Инспектор» справа покажет контекст: метку, тип,
   дату и метрики. Чего в данных нет, панель честно пометит «н/д».
4. Переключитесь на «Профили»: менеджер профилей измерений и превью их
   комбинации.
5. Если сессий больше 200, кнопка «Загрузить ещё» догружает следующую страницу
   (курсорная пагинация, страница 200 записей).

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| «Состояние (health)» | Выпадающий список: пустое значение («Все») или одно из состояний сессии. |
| «Метка» | Поиск по метке сессии. |
| «Тип сессии» | «Все», `capture`, `simulate`, `line_quality`. |
| «Дата с» / «Дата по» | Границы диапазона дат создания. |
| «Профиль» / «Тег» | Текстовые фильтры по профилю и тегу. |
| «Сохранённые представления» | Выбор сохранённого набора фильтров; кнопки «Сохранить фильтры…» (диалог с названием), «Удалить представление», «Сбросить». Хранение локальное. |
| «Загрузить ещё» | Следующая страница списка. |
| «Инспектор» / «Профили» | Вкладки правой панели: контекст выбранной сессии или менеджер профилей. |

**Ограничения и состояния ошибок.**

- Загрузка: «Загрузка списка сессий…».
- Пустой список с фильтрами: «По запросу ничего не найдено. Измените параметры
  фильтрации или нажмите „Сбросить“.»
- Пустой список без фильтров: сохранённых сессий нет, панель говорит это
  прямо.
- Ошибка загрузки: блок ошибки с кнопкой повтора.
- Выбранная сессия и фильтры кодируются в URL (параметр `session`), ссылка на
  состояние воспроизводится.

## 2. Захват

**Что делает.** Пошаговый визард записи: режим и источник (шаг 1), параметры
(шаг 2), запуск и слежение за задачей (шаг 3). Подзаголовок страницы: «Три
шага: режим → параметры → запуск», журнал задачи на шаге 3. Слева рельс шагов,
справа колонка «Профиль записи»: живое превью того, что уйдёт в
`POST /api/jobs`.

**После быстрого старта.** Визард стоит на шаге 1, по умолчанию выбраны режим
«RC-измерение (двухканальное)» и источник «Симулятор». Хронология задачи на
шаге 3 пуста и приглашает запустить первый захват.

### Типовой сценарий: симулятор, без железа

1. Откройте «Захват». Шаг 1: режим «RC-измерение (двухканальное)», источник
   «Симулятор». Нажмите «Далее: параметры».
2. Шаг 2: проверьте длительность 2,4 с и частоту дискретизации 8 000 000 Гц.
   Раскройте «Серия и протокол» и выберите профиль симуляции, например `bad`.
   Нажмите «Далее: запуск».
3. Шаг 3: нажмите «Запустить запись». Хронология покажет стадии «симуляция»,
   «анализ», затем «готово»; в списке записанных сессий появится ссылка в
   инспекцию (`#/inspect?a=<id>`), когда сессия проанализирована.
4. «Проверить устройство» на этом же шаге покажет, что осциллограф не
   обнаружен: без железа это типизированное состояние, а не авария.

### Типовой сценарий: риппл-измерение на осциллографе

1. Подключите адаптер: конденсатор у точки измерения, земля на DC-return той
   же линии. Не переподключайте адаптер в эпоху записи.
2. Шаг 1: режим «Риппл-измерение (адаптер)», источник «Осциллограф Hantek
   6022BE».
3. Шаг 2: задайте длительность с запасом от пола анализа (секция подскажет,
   если не хватает), заполните «Декларацию адаптера» и отметьте галку
   подключения. Нажмите «Далее: запуск».
4. Шаг 3: «Проверить устройство», затем «Запустить запись». Стартуйте сразу
   после подключения адаптера: первые 10τ установления движок отбросит.
5. После завершения откройте сессию в «Инспекции»: панель «Риппл / шум»
   раздаст сохранённый артефакт.

### Шаги визарда

**Шаг 1, «Режим измерения» (что пишем).** Radio-карточки режимов измерения и
radio-карточки источника записи. Режим фиксирует каналы и вход: невозможные
комбинации недоступны. Кнопка «Далее: параметры».

**Шаг 2, «Параметры записи» (как пишем).** Сверху чипы-эхо: выбранный режим,
«симулятор» или «осциллограф», «каналы: N», тип сессии. Дальше сетка
настроек, секция «Декларация адаптера» (только риппл-режим с осциллографом) и
раскрытие «Серия и протокол». Кнопки «Назад: режим» и «Далее: запуск»;
«Далее» блокируется валидацией, ошибки рисуются на полях, фокус уходит на
первое невалидное поле. Внизу панели счётчик «Шаг 2 из 3».

**Шаг 3, «Запуск и прогресс» (задача и журнал).** Строка алерта, кнопки
«Запустить запись» и «Проверить устройство», панель устройства, живая
спектрограмма и хронология задачи. Кнопка «Назад: параметры». Подзаголовок
напоминает: «Проверьте профиль: это то, что уйдёт в POST /api/jobs.»

Deep-link из инспекции (`#/capture?mode=…&source=…&duration_s=…` и другие
параметры) заполняет форму и открывает шаг 2. Если на сервере жива активная
или прерванная задача, вкладка открывается сразу на шаге 3 с предложением
восстановления.

### Режимы измерения

| Режим | Каналы | Вход | Самошум | Базовая сессия | Тип сессии |
|---|---|---|---|---|---|
| «RC-измерение (двухканальное)» | 2 | rc | нет | применяется | «Измерение (measurement)» |
| «Терминированный самошум» | 2 | rc | да | не применяется | «Самошум (self_noise)» |
| «Качество сети (трансформатор 230:6)» | 1 | transformer | нет | не применяется | «Качество сети (line_quality)» |
| «Одноканальный захват» | 1 | rc | нет | применяется | «Измерение (measurement)» |
| «Риппл-измерение (адаптер)» | 1 | rc | нет | не применяется | «Измерение (measurement)» |

Что измеряет каждый режим:

- **RC-измерение.** CH1 подключён к ВЧ-фронтенду RC, CH2 к трансформатору
  50 Гц для фазовой привязки. Доступны все метрики: спектр, пики, иголки.
- **Терминированный самошум.** Фронтенды отключены, входы терминированы
  50 Ом: прибор пишет собственный шум. Такая сессия служит базой: её спектр
  нужен, чтобы привести спектр CH1 измерения ко входу. Базовая сессия в этом
  режиме не задаётся.
- **Качество сети.** Один пробник на вторичке трансформатора 230:6,
  переключатель пробника в 10x. Метрики: частота сети, RMS, THD и гармоники.
- **Одноканальный захват.** Только CH1, без привязки к фазе. Спектр и пики
  считаются, метрики CH2 будут «н/д».
- **Риппл-измерение.** Тот же одноканальный поток CH1, но с адаптером
  AC-связи: последовательный конденсатор у точки измерения (пресет 100 нФ,
  вход 1 МОм, пробник x1). Измеряет пульсации и шум на DC-линии питания:
  числа RMS AC и Vpp в полосе анализа и спектр (PSD/ASD) в артефакте сессии.
  Схема адаптера и правила подключения описаны в
  [ripple-measurement-ru.md](ripple-measurement-ru.md).

### Источник записи

| Источник | Что делает |
|---|---|
| «Симулятор» | Синтетическая запись без железа, задача уходит с `kind:"simulate"`. Безопасно для автоматизации. |
| «Осциллограф Hantek 6022BE» | Реальная запись, задача уходит с `kind:"capture"`. Требует готового устройства и пройденного preflight. |

### Поля формы

| Поле | Опции и границы |
|---|---|
| «Длительность, с» | Число, по умолчанию 2,4, минимум 0,01, шаг 0,1. Движок требует не меньше 100 периодов сети: 2 с при 50 Гц. |
| «Частота дискретизации, Гц» | Число, по умолчанию 8 000 000. Подсказка поля: АЦП осциллографа до 8…24 МГц, симулятор допускает любые значения. |
| «Диапазон CH1» | «5 В», «1 В», «0,5 В»; по умолчанию 5 В. |
| «Каналы» | Строка-проекция режима, не контрол: «Каналы: 2 (CH1 + CH2)» или «Каналы: 1 (только CH1)». |
| «Базовая сессия (самошум)» | Имя сессии самошума этой локации; спектр CH1 будет приведён ко входу. Пусто, если база не нужна. Латиница, цифры, `._-`, до 128 символов. Видно только у режимов с базой. |
| «Метка» | Текст до 128 символов. |
| «Повторов, шт.» | Целое от 1, по умолчанию 1. Серия повторных записей, каждая сессия пишется отдельно. |
| «Интервал стартов, с» | Число от 0, по умолчанию 0. |
| «Профиль симуляции» | `bad`, `bad-damped`, `quiet`, `sync-only`, `async-heavy`; по умолчанию `quiet`. Только для симулятора. |

### Декларация адаптера (риппл-режим)

Секция появляется на шаге 2 только при режиме «Риппл-измерение» и источнике
«Осциллограф». Симулятор и остальные режимы ключ `adapter_declaration` в
запрос не получают вовсе.

Требование декларации: риппл-числа публикуются только с подтверждённой схемой
подключения. Декларация записывается в контекст сессии в момент захвата и
дальше не меняется (write-once).

| Контрол | Что делает |
|---|---|
| Галка «Адаптер подключён до старта, переподключений в эпохе записи не было» | По умолчанию не отмечена. Без отметки публичные числа ripple недоступны (`settling_unknown`). |
| «Ёмкость C, нФ» | Ёмкость адаптера, префилл 100, положительное число. |
| «Последовательный R, Ом» | Рядное сопротивление, префилл 0, неотрицательное число. |
| «Базис значений» | Радио-пара «номинал» / «измерено оператором», по умолчанию «номинал». Базис выбирает оператор; совпадение чисел с номиналом его не меняет. |

Тракт записи фиксирован и полями не редактируется: вход осциллографа 1 МОм
(номинал), пробник x1.

Динамика секции:

- пока галка не отмечена, держится подсказка: подключите адаптер и стартуйте
  сразу, первые 10τ установления движок отбросит;
- если заданной длительности не хватает до пола анализа, появляется
  консультативное сообщение вида «При C=… нФ и fs=… Гц окну анализа нужно ≥… с
  записи». Это зеркало расчёта движка, а не второй источник истины.

### Валидация до отправки

Клиент проверяет форму до «Далее: запуск»:

- длительность: положительное число секунд;
- частота дискретизации: положительное число герц;
- диапазон: 5, 1 или 0,5 В;
- повторы: целое от 1; интервал: неотрицательное число секунд;
- имя базовой сессии: латиница, цифры, `._-`, до 128 символов;
- метка: до 128 символов;
- декларация: C положительна, R неотрицателен, базис один из двух литералов.

При ошибках объявляется «Форма содержит ошибки: исправьте выделенные поля.»,
фокус уходит на первое невалидное поле. Сервер зеркалит эти границы и добавляет
свои: самошум не принимает базовую сессию, трансформаторный вход работает
только с одним каналом и без базы, имя выходного каталога обязано быть
безопасным дочерним именем.

### Запуск и ход задачи

Поток запуска:

1. Панель берёт bootstrap-nonce ровно один раз. Нет связи с сервером: «Нет
   связи с сервером: панель не инициализирована. Повторите попытку.»
2. Если задача уже выполняется, старт блокируется с видимой причиной. HTTP 409
   от сервера даёт: «Сервер сообщил конфликт: уже выполняется другая задача
   (HTTP 409).» В панели живёт одна задача.
3. Для осциллографа панель сначала читает состояние устройства и прогоняет
   preflight. Устройство не готово: «Запуск невозможен: устройство не готово.
   Выполните указанное диагностикой действие.» Блокирующие замечания preflight:
   «Запуск невозможен: preflight нашёл блокирующие замечания, см. панель
   устройства.»
4. «Запустить запись» уходит `POST /api/jobs` и дизейблится на время запроса.

Хронология «Активная задача» на шаге 3:

- строки статуса и стадии: «в очереди», «симуляция», «захват», «анализ»,
  «сравнение», «самопроверка», «проверка устройства», «резервное копирование»,
  «сборник поддержки», «готово»;
- позиция серии «Серия i из N» с прогресс-баром;
- список записанных сессий со ссылками в инспекцию (`#/inspect?a=<id>`);
- «Отменить после текущей сессии» с подтверждающим диалогом: «Отмена будет
  выполнена на безопасной границе: после завершения текущей записи серии.
  Подтвердить отмену?» Отмена не рвёт текущую запись;
- «Повторить задачу» повторяет последний запрос после неудачи, отмены или
  прерывания. Если сохранённого запроса нет (например, после перезапуска
  сервера): «Нет сохранённого запроса для повтора. Запустите новую запись
  через форму.»
- потеря связи: «Связь с задачей прервана, ожидаем восстановление…».

События задачи идут по SSE `GET /api/jobs/{id}/events`; после 4 с тишины панель
переключается на опрос `GET /api/jobs/{id}`.

Живая спектрограмма на шаге 3: кольцо 48 столбцов времени на 256 бинов частоты,
пол −120 дБ, обновление опросом каждые 1500 мс, пока задача активна; после
завершения один финальный запрос. Нет данных: пустое состояние, не ошибка.

**Ограничения и состояния ошибок.**

- Одна задача на панель: повторный старт даёт 409, отмена завершает текущую
  сессию и останавливается на границе.
- Риппл-декларация допускается только одноканальным RC-захватом без самошума
  (валидатор бэкенда).
- Блокировки preflight и неготовность устройства показываются причиной и
  следующим действием, а не общим отказом.
- `output_name` и `seed` модель запроса имеет, но форма не экспонирует: имя
  выходного каталога собирает бэкенд, семя симуляции фиксируется профилем и
  сервером.

## 3. Осциллограф

**Что делает.** Живой режим развёртки: непрерывный поток кадров, Run/Stop и
статус владения прибором. Кадры идут по SSE (`GET /api/live/frames`),
состояние контура читается через `GET /api/live/state`.

**После быстрого старта.** Прибора нет. Панель «Прибор» покажет строку
диагностики: `device_absent`, «Hantek DSO-6022BE не обнаружен на USB» с
действием «Подключите устройство и проверьте кабель/порт». Кнопка «Запустить»
завершится ошибкой «Не удалось запустить живой режим: …». Это честное
поведение: вкладка без железа не рисует ничего похожего на измерение.

**Типовой сценарий (с прибором).**

1. Откройте вкладку и дождитесь строки устройства: должно быть `ready`
   («Устройство, WinUSB и RAM-прошивка готовы»).
2. Задайте вертикаль: «В/дел (оба канала)», «Пробник CH1», при необходимости
   инверсию каналов. Задайте частоту дискретизации.
3. Задайте триггер: источник, полярность, режим, уровень. Нажмите «Запустить».
4. Строка статуса сменится на «Живой режим: запущен», развёртка пойдёт. Панель
   «Поток» показывает счётчики кадров и точек.
5. Подстройте триггер на ходу: изменения уходят `POST /api/live/config`,
   захват не перезапускается.
6. Прочитайте измерения по кадру; в риппл-тракте смотрите живой риппл-чип.
   Поставьте курсоры и снимите Δ между ними.
7. Нажмите «Остановить». Уход с вкладок «Осциллограф» и «Спектроанализатор»
   тоже останавливает захват.

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| «Запустить» / «Остановить» | `POST /api/live/start` / `POST /api/live/stop` с nonce. Тело запуска несёт диапазон АЦП из В/дел, пробник, частоту и триггер. |
| «В/дел (оба канала)» | Чип-меню из девяти шагов: 5 В, 2 В, 1 В, 0,5 В, 0,2 В, 0,1 В, 50 мВ, 20 мВ, 10 мВ. Применяется при запуске. |
| «Пробник CH1» | Сегмент ×1 / ×10. |
| «Инверсия CH1» / «Инверсия CH2» | Чекбоксы инверсии каналов. |
| «В/дел CH1 (с пробником)» | Строка эффективной цены деления. |
| Частота дискретизации | Чип с девятью опциями из таблицы прибора: 20 кГц, 50 кГц, 100 кГц, 200 кГц, 500 кГц, 1 МГц, 2 МГц, 4 МГц, 8 МГц; по умолчанию 8 МГц. На ходу не меняется, применяется при запуске. |
| Триггер: источник, полярность, режим, «Уровень, В» | Источник CH1/CH2, полярность «Подъём»/«Спад», режимы «Авто»/«Норм»/«Одиночный», уровень от -5 до +5 В. |
| «Полоса (отображение)» | Программный ФНЧ отрисовки кадра: «Полная», «~5 МГц», «~1 МГц». |
| «Послесвечение (отображение)» | Затухание следа прошлых кадров: «Выкл», короткое около 0,5 с, длинное около 2 с. |
| Измерения | По кадру на канал: Vpp, Vmax, Vmin, RMS, частота, период, скважность. |
| Живой риппл-чип | Оверлей в стекле осциллографа: состояние («установление», «недоступно», «готов», «остановлен», «нет данных»), числа RMS AC и Vpp, окно, параметры адаптера, базис. |
| Курсоры | Драгаемые линии с Δ-отсчётами между ними. |

**Ограничения и состояния ошибок.**

- Режимы триггера: «Авто» даёт кадр по таймауту 0,2 с даже без фронта; «Норм»
  только по фронту; «Одиночный» даёт один кадр и отпускает прибор, панель
  подтверждает остановку.
- Уровень вне диапазона отклоняется до отправки: «Уровень триггера должен быть
  в диапазоне от -5 до 5 В.»
- Связи входов только DC; holdoff и предтриггерной памяти у Hantek 6022BE нет,
  панель их не показывает.
- «Полоса (отображение)» и «Послесвечение (отображение)» меняют только
  картинку, подпись это говорит прямо: программный фильтр, не аналоговый
  предел; накопление это отображение, не измерение. Измерения всегда считаются
  по нефильтрованным отсчётам. Отсчёты 8-битного АЦП, вольты без калибровочных
  заявлений.
- Плоский или нулевой кадр, меньше двух фронтов: измерения показывают
  прочерк, а не случайные числа.
- Живые риппл-числа используют номинальную модель адаптера; ввода декларации
  в живом режиме нет. Числа гаснут сразу при потере транспорта.
- Живой контур один: повторный старт даёт 409. Мёртвая вкладка (упал браузер,
  оборвался SSE) теряет прибор примерно через 10 с без опроса.
- Ошибки показываются блоком в статусе: «Не удалось запустить живой режим: …»,
  «Не удалось остановить живой режим: …», «Не удалось применить триггер: …»,
  «Не удалось получить состояние устройства: …».

## 4. Спектроанализатор

**Что делает.** Живые трассы спектра поверх того же захвата: clear-write,
min/max-hold и бегущее среднее; полоса и RBW настраиваются на ходу.

**После быстрого старта.** Как и у осциллографа: без прибора запуск завершится
ошибкой, панель «Настройки анализа» настраивается, но данных нет.

**Типовой сценарий (с прибором).**

1. Запустите живой захват здесь или на «Осциллографе». Уже идущий поток
   вкладка не перезапускает: она присоединяется к нему и настраивает SA-контур
   через `POST /api/live/config`.
2. Задайте RBW, окно, детектор и полосу; на ходу изменения уходят конфигом.
3. Включите нужные трассы: «Max-hold», «Min-hold», «Среднее». При смене полосы
   сбросьте статистику кнопкой «Сбросить статистику».
4. Поставьте маркеры кликом по полю графика или кнопкой «Найти пики»; не
   больше четырёх.
5. Нажмите «Остановить». Уход с вкладки гасит SA-контур, захват живёт до
   выхода из группы live-маршрутов.

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| «Запустить» / «Остановить» | Живой контур, общий с «Осциллографом». |
| «RBW, Гц» | Сегменты 10 / 30 / 50 / 100 / 300. |
| «Окно» | Ханн, Флэт-топ, Кайзер, Блэкман, Прямоугольное. |
| «Детектор» | Среднее, RMS, Max-hold, Min-hold. Выборки нет. |
| «Начало полосы, Гц» / «Конец полосы, Гц» | Границы полосы анализа. Локально отсекается только пустая или перевёрнутая полоса; геометрию против Найквиста проверяет сервер. |
| «Трасса» | Живая clear-write трасса, не отключается. |
| «Max-hold» / «Min-hold» / «Среднее» | Накопительные трассы. |
| «Сбросить статистику» | Обнуляет накопление трасс. |
| «Единицы» | дБВ/Гц и В/√Гц. |
| «Лог. шкала X» | Логарифмическая ось частот, по умолчанию выключена. |
| Маркеры | До 4 пользовательских маркеров: клик по полю задаёт частоту, уровень читается по живой трассе (максимум ±1 бин с параболическим уточнением). «Найти пики» отбирает пики последнего свипа по prominence, «Убрать маркеры» снимает все. |

**Ограничения и состояния ошибок.**

- Перевёрнутая или пустая полоса: «Полоса пуста: начало должно быть ≥ 0 и
  меньше конца.» Полоса против Найквиста проверяется сервером, панель покажет
  ошибку ответа.
- Трассы и маркеры считаются и живут на клиенте: сервер их не хранит,
  перезагрузка страницы снимает их.
- Индикатор соединения показывает «передача данных» или «переподключение…»;
  ошибки запуска и применения настроек выводятся в статус: «Не удалось
  запустить живой режим: …», «Не удалось применить настройки SA: …».

## 5. Инспекция

**Что делает.** Детальный анализ пары сессий: выбор A (база) и B (сравнение),
спектр мощности и спектрограмма, дельты B − A, таблица маркеров, панель
«Риппл / шум», панели analysis-v2 и билет в захват. Раскладка: сверху полоса
пары A/B, ниже слева рейл каталога, справа основной блок, снизу командбар.

**После быстрого старта.** Пара выбирается автоматически: первые две
проанализированные сессии, свежая становится базой A. С двумя сессиями
быстрого старта «розетка-Б» (quiet, записана второй) встанет в A, «розетка-А»
(bad) в B. Дельты покажут bad относительно quiet: на звоне 22,4 кГц ожидается
около +26 дБ. Полоса анализа CH1: от 3 кГц до min(3 МГц, 0,45 × fs).

**Типовой сценарий.**

1. Откройте «Инспекцию»: пара уже выбрана, спектр построен.
2. Проверьте слоты полосы пары: роли «База» и «Сравнение», глиф состояния,
   имя, тип и дата, путь B. Бейджи «Δср …» и «Δmax …» показывают среднюю и
   максимальную |Δ| по PSD в дБ.
3. Смените пару при необходимости: клик по строке рейла назначает сессию в
   следующий слот, кнопки «А» и «Б» у строки назначают точно, «Поменять
   местами» меняет A и B. Состояние пары живёт в URL (параметры `a` и `b`) и
   переживает перезагрузку.
4. Изучите спектр: вид «Спектр», плоскость «Скоп» или «Вход», селекторы
   маркеров RBW и окна.
5. Переключите вид на «Спектрограмма»: парные A/B спектрограммы с
   выравниванием.
6. Прочитайте Δ-полосу под спектром, Δ-чипы пиков и колонку «Δ B−A, дБ» в
   таблице маркеров.
7. Для риппл-сессии откройте панель «Риппл / шум».
8. Командбар снизу: поля будущего захвата и кнопка «Запустить захват», она
   уводит на «Захват» с заполненной формой.

### Выбор сессий A/B

- Клик по строке рейла каталога назначает сессию в следующий слот; кнопки «А»
  и «Б» у каждой строки назначают слот точно.
- Клик по слоту полосы пары пару не меняет: фокус уходит на первый ряд рейла,
  кнопки назначаемого слота подсвечиваются.
- «Поменять местами» недоступна, пока B не выбран.
- При входе без параметров URL авто-выбор берёт первые две проанализированные
  сессии (свежая выше). Кандидатов нет: пара пустая, причины видны в рейле.
- Сессии «Качество сети» (line_quality) в A/B не сравниваются: их метрики
  открываются поодиночке.

### Дельты: всегда B − A

Конвенция проекта: дельта всегда «B − A», сравнение с базой. Дельты видны в
четырёх местах:

- бейджи «Δср» и «Δmax» полосы пары: средняя и максимальная |Δ| по PSD, дБ;
  без пары прочерк;
- Δ-полоса под спектром: заголовок «Δ = B − A, дБ · ±8», кривая
  10·log10(B/A) с клипом ±8 дБ; сворачивается с памятью, по умолчанию
  раскрыта; без пары «Выберите пару для Δ»;
- Δ-чипы пиков отображаемой плоскости;
- колонка «Δ B−A, дБ» таблицы маркеров.

Сравнивать нужно дельты, а не абсолютные значения. Абсолютный уровень зависит
от пробника, длины проводов и положения рук; дельта между двумя записями одной
серии зависит от них существенно меньше. Точность дельт ограничена рендером
спектра (около 0,1 дБ), побитового совпадения нет.

### Спектр и спектрограмма

Шапка секции «Спектр мощности · Гц» собрана кластерами «Вид», «Спектр» и
«Спектрограмма».

| Контрол | Что делает |
|---|---|
| «Вид»: «Спектр» / «Спектрограмма» | Переключение основного графика. Кластер спектрограммы не исчезает в режиме спектра: его состояние читается всегда, приглушённо. |
| «Пересчитать спектр» | Повторная загрузка спектра. |
| «Спектр»: «Скоп» / «Вход» | «Скоп» это сырой CSV-спектр; «Вход» это приведённый ко входу избыточный PSD. Приведение недоступно: кнопка дизейблится с причиной в подсказке, показ тихо возвращается на «Скоп». |
| «RBW ≈ … Гц» | Подпись разрешающей полосы: 1,5 × шаг сетки частот (ENBW окна Ханна). |
| Селекторы маркеров RBW и окна | RBW 10/30/50/100/300 Гц; окно Ханн, Флэт-топ, Кайзер, Блэкман, Прямоугольное. |
| «Спектрограмма» | Парные A/B спектрограммы с выравниванием. |

Конвенции отображения: ось в дБ относительно 1 В²/Гц, никогда «голый дБ»;
децимация отображения агрегирует максимумом; пропавшие бины не заполняются
нулями.

### Таблица маркеров

«Маркеры спектра» под графиком: строки «Пик 1…N» из анализа, гармоники
«H2…H40» от сильнейшего пика (пока частота попадает в сетку) и строка «СКЗ
полосы» (из анализа либо честная пометка «оценка по дисплею»).

Колонки: «Маркер», «Частота, Гц», «Уровень, <единица>» и «Δ B−A, дБ», когда
задана пара B. Пиков нет: строка «Пики не найдены».

Переключатель единиц меняет только отображение: дБВ, дБмкВ, дБм(50 Ом). CSV
хранит В²/Гц, дельты от единиц не зависят.

В быстром старте у «розетки-А» (bad) в таблице будет выраженный пик около
22,4 кГц; у «розетки-Б» (quiet) тот же звон слабее. Колонка Δ на этой частоте
покажет разницу двух профилей.

### Панель «Риппл / шум»

Раздаёт сохранённый ripple-артефакт базовой сессии пары одним запросом
`GET /api/sessions/{name}/ripple`. Переключатели PSD/ASD и выбор полосы не
порождают новых запросов. Маршрут read-only, параметров запроса не имеет.

В быстром старте панели нечего показывать: у симулированных RC-сессий
ripple-артефакта нет, будет честный 404.

Ошибки: артефакт отсутствует, 404. Конфликт согласованности, 409 с причиной
(«файл повреждён», «схема не совместима с v1», «входные файлы изменились»,
«файл сайдкара небезопасен») и советом запустить анализ ripple заново.

### Панели analysis-v2 и командбар

- Панели analysis-v2 читают артефакты v2 (`GET /api/sessions/{name}/artifacts/…`);
  ход задачи виден через общий job-контур. Во время задачи контролы полосы
  пары блокируются, после успеха данные пары перезабираются тем же конвейером.
- Командбар: поля «Режим» (2 канала / 1 канал), «Источник» (устройство /
  симуляция), «Длительность с», «Частота Гц», «Диапазон CH1» (±2 В / ±5 В),
  «Метка» и кнопка «Запустить захват». Кнопка уводит на `#/capture` с
  префиллом: значения переводятся в параметры визарда, «±2 В» заменяется
  ближайшим легальным «1 В», подмена видна в форме. Рядом живой статус
  устройства: «Устройство готово» или «Устройство не готово» со следующим
  действием.
- Ошибки загрузки выводятся лентой наверху вкладки; протухший график на
  экране не остаётся.

## 6. Эксперименты

**Что делает.** Группировка сессий по протоколам (A/B, A/B/A, повторные
серии): создание эксперимента, назначение участников с условиями, наблюдение
протокола, сверка участников, сравнение групп, тренды и гипотезы.

**После быстрого старта.** Экспериментов нет: список покажет пустое состояние.
Для работы нужен хотя бы один созданный эксперимент.

**Типовой сценарий.**

1. Нажмите «Новый эксперимент…»: мастер создаёт протокол с таймлайном шагов;
   участники получают условия по вашему назначению.
2. В секции «Сессии и условия» назначьте участникам условия селектами;
   остальным оставьте вариант «не участвует». С двумя сессиями быстрого
   старта получится простое A/B.
3. Сохраните. Слева появится кнопка «<название> (<id>)»; выбор кодируется
   параметром `experiment` в URL.
4. Вкладки правой колонки: «Обзор» (таймлайн протокола и таблица участников с
   QC и исключениями), «Сравнение» (A/B, A/B/A, повторные серии), «Тренды»,
   «Гипотезы». Вкладки ленивые: содержимое строится при первом открытии.
5. «Обновить» перечитывает список.

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| «Новый эксперимент…» | Мастер протокола: шаги, участники, условия. |
| «Обновить» | Перезапрос списка экспериментов. |
| Список слева | Кнопки «<название> (<id>)», выбор живёт в URL. |
| «Обзор» / «Сравнение» / «Тренды» / «Гипотезы» | Вкладки правой колонки. |
| Селекты «Сессии и условия» | Назначение условий участникам, вариант «не участвует». |

**Ограничения и состояния ошибок.**

- Загрузка: «Загрузка списка экспериментов…»; ошибка с кнопкой повтора; пусто:
  «Экспериментов пока нет.»
- Пустой каталог в мастере: «Каталог сессий недоступен.» или «Нет сессий в
  каталоге.»

## 7. Отчёты

**Что делает.** Сборка отчёта из данных выбранного эксперимента с полной
прослеживаемостью (provenance) и выгрузка в `.md`.

**После быстрого старта.** Отчёт начинается с выбора эксперимента. Пока слева
ничего не выбрано, справа приглашение выбрать эксперимент, кнопка сборки
недоступна.

**Типовой сценарий.**

1. Выберите эксперимент слева. Если его нет, создайте в «Экспериментах».
2. Задайте «Единицы» (текстовое поле).
3. Нажмите «Собрать отчёт»: сборка идёт через
   `POST /api/experiments/{id}/statistics-runs` и
   `GET /api/statistics-runs/{job_id}/result`; превью покажет данные и
   provenance.
4. Нажмите «Скачать отчёт (.md)»: файл собирается на клиенте.
5. Смена единиц требует пересборки: панель напомнит собрать отчёт заново.

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| Список экспериментов + «Обновить» | Выбор источника данных. |
| «Единицы» | Текстовое поле единиц отчёта. |
| «Собрать отчёт» | Запуск статистики и превью; доступна после выбора эксперимента. |
| «Скачать отчёт (.md)» | Выгрузка собранного отчёта; доступна после сборки. |

**Ограничения и состояния ошибок.**

- Маршрутов отчётов на бэкенде нет: превью и файл собираются клиентом,
  интерфейс заявляет это прямо.
- Ограничения (limitations) выводятся из данных, не выдумываются; деградация
  данных видна отдельным сообщением.
- Ошибки: «Сервер недоступен: …» с повтором; «Сборка не выполнена: …» с
  советом проверить выбранный признак и данные сессий.

## 8. Настройки

**Что делает.** Корень сессий с локальной заметкой, диагностика устройства и
готовности захвата, бэкап и сборник поддержки, переход к профилям, сводка
приватности и рецепты анализа.

**После быстрого старта.** «Корень сессий» покажет каталог, переданный
`--root` (в примере это `$demo`). «Проверить устройство» вернёт `device_absent`
«Hantek DSO-6022BE не обнаружен на USB»: это типизированное штатное состояние,
не авария. «Проверить готовность захвата» прогонит preflight по живой форме
захвата.

**Типовой сценарий.**

1. Проверьте «Корень сессий»: фактический корень, локальная заметка с кнопкой
   сохранения, блок выбора корня с копированием.
2. Нажмите «Проверить устройство»: состояние цепочки backend, USB и прошивки с
   описанием и следующим действием.
3. Нажмите «Проверить готовность захвата»: панель «Готовность захвата»
   перечислит замечания; чистый прогон даёт «Замечаний нет.»
4. «Создать бэкап» (задача `backup`) и «Собрать сборник» (задача
   `support_bundle`): задачи идут через `POST /api/jobs` с SSE-прогрессом,
   статус виден на месте. Запасной путь для обеих операций это CLI.
5. «Открыть управление профилями в каталоге»: переход на `#/catalog`.

**Ключевые контролы.**

| Контрол | Что делает |
|---|---|
| «Корень сессий» | Фактический корень из `GET /api/config`, заметка, блок выбора корня. |
| «Проверить устройство» | Состояние устройства: код, описание, следующее действие. |
| «Проверить готовность захвата» | Preflight из живой формы захвата, список замечаний. |
| «Создать бэкап» | Задача `backup` с SSE-прогрессом. |
| «Собрать сборник» | Задача `support_bundle` с SSE-прогрессом. |
| «Профили» | Ссылка на менеджер профилей в каталоге. |
| «Рецепты анализа (только чтение)» | Просмотр рецептов. Удаление рецепта бэкенд отклоняет (409): на рецепты ссылаются опубликованные артефакты. |

**Ограничения и состояния ошибок.**

- Корень недоступен: значение «недоступно (сервер не отвечает)» с сообщением
  «Корень сессий недоступен: …» и кнопкой «Повторить».
- Задачи бэкапа и сборника сообщают ошибки вида «не выполнено: …».
- Отсутствие прибора в диагностике это типизированное состояние, не ошибка.
